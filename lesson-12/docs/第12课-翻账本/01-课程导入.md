# 第12课 · 课程导入：翻账本（分页与联表查询）

## 上一课发生了什么

事务兜住了底，账本终于可靠了。但对**订单**，你目前只用过两种查法：`findById`（查一张）和 `findAll`（**查所有**）。

想象营业一个月后：`findAll` 一次性把上万条订单连同明细全部查出来塞进 JSON——数据库吃力、网络吃力、浏览器卡死。真实世界没人这么翻账本：**翻账要一页一页翻**。

今天的三个新需求，对应三件新武器：

| 需求 | 武器 |
|---|---|
| 一页一页看订单，最新在前 | `Pageable` + `Sort`（JpaRepository 自带，方法都不用写） |
| 查一张订单的详情 | `findById` + 新错误码 40402 |
| "谁点过回锅肉？"——菜名在明细表里，要跨两张表查 | `@Query` + JPQL 联表 |

## 先想清楚：分页在数据库层面是怎么发生的？

你在 h2-console 或任何 SQL 客户端里翻大表，用的就是这两句：

```sql
select ... from t_order order by create_time desc   -- 按时间倒序（最新在前）
limit 2 offset 0                                     -- 跳过 0 行，取 2 行（H2 方言是 offset/fetch）
```

"第 0 页每页 2 条" = `offset 0, limit 2`；"第 1 页" = `offset 2, limit 2`。**页码从 0 开始**是程序员世界的约定（数组下标同款逻辑），第 12 课的思考题会让你体会它的好处。

JPA 把这些翻译成了一个对象：`PageRequest.of(page, size, sort)`——你只说"第几页、每页几条、按什么排"，SQL 它来拼。同时它还会**自动多发一条 count 查询**拿总条数——不然前端怎么知道一共几页、要不要显示"下一页"按钮？

## 本课你将学会

1. `findAll(Pageable)` 分页查询 + `Sort` 排序（一个方法都不用自己写）
2. `Page<T>` 的结构：records / totalElements / totalPages / pageNum / pageSize
3. `@Query` + JPQL：面向对象写联表查询，join 的是**实体关联字段**而不是表
4. `@PathVariable`（路径变量）与路由的精确匹配优先规则
5. 前端第三次进化：翻账本按钮
