## Step 2：OrderRepository 加联表查询（15 分钟）

`dao/OrderRepository.java` 升级为"查询武器库"：

```java
package com.cdutetc.nanpo.dao;

import java.util.List;

import org.springframework.data.jpa.repository.JpaRepository;
import org.springframework.data.jpa.repository.Query;
import org.springframework.data.repository.query.Param;

import com.cdutetc.nanpo.entity.Order;

/**
 * 订单的数据访问接口。
 * 明细（t_order_item）靠 Order 上的 cascade=ALL 级联保存，
 * 所以暂时不需要单独的 OrderItemRepository。
 *
 * 第12课：查询武器库——
 * 分页 findAll(Pageable) 由 JpaRepository 自带（不用写方法）；
 * 联表查询用 @Query + JPQL：面向对象写 SQL，join 的不是表而是实体关联字段。
 */
public interface OrderRepository extends JpaRepository<Order, Long> {

    // "谁点过这道菜"：订单表没有菜名字段，跨 t_order/t_order_item 两表查。
    // JPQL 里 join 的是实体的关联属性 o.orderItems，数据库会自动翻译成
    // t_order join t_order_item on order_id = id
    @Query("select distinct o from Order o join o.orderItems i where i.dishName = :dishName")
    List<Order> findByDishName(@Param("dishName") String dishName);
}
```

对比 SQL 理解 JPQL（Java Persistence Query Language）：

| SQL（数据库视角） | JPQL（Java 对象视角） |
|---|---|
| `from t_order o join t_order_item i on o.id = i.order_id` | `from Order o join o.orderItems i` |
| join **表**，手写 on 条件 | join **实体的关联字段**，on 自动带出 |
| `where i.dish_name = ?` | `where i.dishName = :dishName` |
| 列名 `dish_name` | 属性名 `dishName` |

一句话：**JPQL 是"面向对象版的 SQL"**——你操作的是类和属性，Hibernate 负责翻译成表和列。换数据库（第 19 课 H2→MySQL）时 SQL 方言差异它也替你抹平。`distinct` 的作用：一张订单点了两份回锅肉，join 出两行，去重后订单只出现一次。

## Step 3：分页小票 OrderPageVO（10 分钟）

新建 `vo/OrderPageVO.java`：

```java
package com.cdutetc.nanpo.vo;

import java.util.List;

import lombok.Data;

/**
 * 分页小票 VO（出参）：翻账本的一页。
 * 第12课新增：字段对应 Spring Data 的 Page 概念——
 * records(本页数据)/totalElements(总条数)/totalPages(总页数)/pageNum(页号，从0起)/pageSize。
 * 注意 VO 是纯数据类，不 import 框架类型——Page 的组装转换留在 Service 层。
 */
@Data
public class OrderPageVO {

    private List<OrderVO> records;
    private Long totalElements;
    private Integer totalPages;
    private Integer pageNum;
    private Integer pageSize;
}
```

第 10 课的规矩延续：VO 是纯数据类，**不 import 任何框架类型**——Spring Data 的 `Page` 对象不出 Service。组装转换下一步在 Service 做。

## Step 4：OrderService 三个查询方法（20 分钟）

`service/OrderService.java` 在 `createOrder` 之后追加，并补 import（`Page/PageRequest/Sort/List/OrderPageVO`）：

```java
    // ---- 第12课：翻账本（分页/详情/联表查询）----

    /** 分页查订单：页号从 0 开始，按下单时间倒序（最新在前） */
    public OrderPageVO getOrderPage(int page, int size) {
        Page<Order> orderPage = orderRepository.findAll(
                PageRequest.of(page, size, Sort.by(Sort.Direction.DESC, "createTime")));

        // Page → VO 的组装放 Service（VO 不沾框架类型）
        OrderPageVO vo = new OrderPageVO();
        vo.setRecords(orderPage.getContent().stream().map(OrderVO::from).toList());
        vo.setTotalElements(orderPage.getTotalElements());
        vo.setTotalPages(orderPage.getTotalPages());
        vo.setPageNum(orderPage.getNumber());
        vo.setPageSize(orderPage.getSize());
        return vo;
    }

    /** 订单详情：查不到抛业务异常（复用第6课的处理台） */
    public OrderVO getOrder(Long id) {
        return OrderVO.from(orderRepository.findById(id)
                .orElseThrow(() -> new BusinessException(ErrorCodeEnum.ORDER_NOT_FOUND)));
    }

    /** "谁点过这道菜"：JPQL 跨 t_order/t_order_item 联表查询 */
    public List<OrderVO> searchByDish(String dishName) {
        return orderRepository.findByDishName(dishName).stream()
                .map(OrderVO::from)
                .toList();
    }
```

看点：

- `findAll(Pageable)` **不是我们声明的方法**——`JpaRepository` 自带的重载，传分页参数就自动分页。加上 `Sort.by(DESC, "createTime")`：按 createTime 倒序，最新订单第一页第一条。
- `OrderVO::from` 方法引用：流式把每张订单实体转成小票 VO（第 10 课 from() 的复利——新查询出口直接蹭）。
- 三个方法**只读不写**，所以都不需要 `@Transactional`（第 11 课管的是"写"的原子性）。

## Step 5：WaiterController 三个查询接口（15 分钟）

`controller/WaiterController.java` 追加三个 GET 接口（import 补 `PathVariable/RequestParam/List/OrderPageVO`）：

```java
    // ---- 第12课：翻账本 ----

    // 分页查订单：页号从 0 开始（@RequestParam 可带默认值），按下单时间倒序
    @GetMapping("/order/list")
    public Result<OrderPageVO> listOrders(@RequestParam(defaultValue = "0") int page,
                                          @RequestParam(defaultValue = "5") int size) {
        return Result.success(orderService.getOrderPage(page, size));
    }

    // 订单详情：路径变量 /order/1（与 /order/list、/order/search 字面量精确匹配优先）
    @GetMapping("/order/{id}")
    public Result<OrderVO> getOrder(@PathVariable Long id) {
        return Result.success(orderService.getOrder(id));
    }

    // 按菜名查订单："谁点过回锅肉"（JPQL 联表）
    @GetMapping("/order/search")
    public Result<List<OrderVO>> searchByDish(@RequestParam String dish) {
        return Result.success(orderService.searchByDish(dish));
    }
}
```

两个新注解：

- `@RequestParam`：从**查询串**取参数（`?page=0&size=5`），`defaultValue` 让不传也有值——和第 2 课的 `@RequestBody`（从请求体取）凑齐一对。
- `@PathVariable`：从**路径本身**取参数（`/order/1` 里的 `1`）。REST 风格里"资源路径"用它。

**路由优先级问题**：`/order/{id}` 和 `/order/list` 会不会打架？不会——Spring 规则：**字面量精确匹配优先于路径变量**。访问 `/order/list` 走 listOrders，`/order/1` 走 getOrder，`/order/999` 也走 getOrder（然后 40402）。


**③ script 里加函数**：

```js
    // 第12课：翻账本——分页查最近 5 笔订单（page 从 0 开始）
    function loadOrders() {
        fetch('/order/list?page=0&size=5')
            .then(resp => resp.json())
            .then(result => {
                document.getElementById('orders').innerText = JSON.stringify(result, null, 2);
            });
    }
```

重启程序——点餐页多了翻账本按钮，前端第三次进化完成。

> **常见报错**
>
> | 现象 | 原因 | 解法 |
> |---|---|---|
> | `/order/list` 返回 40402 | 手滑写成了 `/order/{id}` 先匹配？不会——检查是否真的加了 list 方法/重启 |
> | 搜索中文菜名 400 Bad Request | 工具没做 URL 编码 | REST Client 一般会自动编码；不行就手工写 `%E5%9B%9E%E9%94%85%E8%82%89`（回锅肉） |
> | 页面按钮没出现 | 浏览器缓存 | 强刷 Cmd/Ctrl+Shift+R |
