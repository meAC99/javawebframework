# 第18课 · 动手做：工具箱 + 双 ChatClient + AI 下单接口

共 5 步。

## Step 1：MenuTool——给 AI 的工具箱（10 分钟）

新建 `service/MenuTool.java`：

```java
package com.cdutetc.nanpo.service;

import java.util.List;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import com.cdutetc.nanpo.dao.MenuRepository;
import com.cdutetc.nanpo.vo.MenuVO;

/**
 * 给 AI 用的工具箱（第18课）：Tool Calling——
 * 大模型自己"不会"查数据库，但可以调用我们注册的工具方法。
 * 工具内部就是第8课的 findAll——AI 和真人顾客走同一套代码、同一个库。
 */
@Component
public class MenuTool {

    @Autowired
    private MenuRepository menuRepository;

    @Tool(description = "获取本店当前完整菜单（菜名、价格、照片路径）")
    public List<MenuVO> getMenu() {
        return menuRepository.findAll().stream().map(MenuVO::from).toList();
    }
}
```

看点只有一个但很关键：**`@Tool(description = "...")`**——这段描述是说给**模型**听的（不是给人）。模型靠它判断"什么时候该调这个工具"。描述写得越准，模型用得越对。方法本体就是普通 Java 方法，返回值会被序列化成 JSON 喂给模型。

## Step 2：AiService 升级——双 ChatClient + 结构化输出（25 分钟，本课核心）

整体替换 `service/AiService.java`：

```java
package com.cdutetc.nanpo.service;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.stereotype.Service;

import com.cdutetc.nanpo.common.BusinessException;
import com.cdutetc.nanpo.common.ErrorCodeEnum;
import com.cdutetc.nanpo.dto.OrderRequest;
import com.cdutetc.nanpo.vo.OrderVO;

/**
 * AI 服务员"小智"。
 * 第17课：基于 Spring AI 的聊天（ChatClient + 人设提示词）。
 * 第18课两项新能力：
 *   ① 工具调用——chatClient 挂上 MenuTool，小智能查"真菜单"回答问题；
 *   ② 结构化输出——orderParser 把"来份不辣的下饭菜"直接解析成 OrderRequest 对象，
 *      随即调用第9课的 OrderService.createOrder()：AI 下单复用全部旧业务，一行不改。
 */
@Service
public class AiService {

    /** 聊天客户端：小智人设 + 带菜单工具（defaultTools——构建期注册，次次可用） */
    private final ChatClient chatClient;

    /** 点单解析客户端：另一个人设（无工具），专职把自然语言变成订单 JSON */
    private final ChatClient orderParser;

    private final OrderService orderService;

    public AiService(ChatClient.Builder chatClientBuilder, MenuTool menuTool, OrderService orderService) {
        this.orderService = orderService;

        // Builder 是可复用的：clone() 出独立副本，各自设置人设，互不串台
        this.chatClient = chatClientBuilder.clone()
                .defaultSystem("你是成都理工大学工程技术学院南坡小炒饭馆的AI服务员，名叫小智。" +
                        "你熟悉川菜家常菜，回答热情简短（两三句话），最后可以自然地引导顾客点单。" +
                        "顾客问菜单相关问题时，先调用工具查真实菜单再回答，不要凭空编造菜品和价格。" +
                        "如果顾客的问题与饭馆无关，礼貌地把话题拉回点餐。")
                .defaultTools(menuTool)
                .build();

        this.orderParser = chatClientBuilder.clone()
                .defaultSystem("你是南坡小炒的点单解析器，只输出 JSON，不输出任何多余文字。" +
                        "把顾客的话解析成点单结构：dishList 里每项是 {\"dishName\":菜名字符串, \"count\":正整数份数}。" +
                        "菜名必须使用菜单上的原样名称（如：回锅肉、米饭）；顾客没说份数默认 1 份；" +
                        "实在识别不出任何菜品时输出空 dishList。")
                .build();
    }

    /** 聊天：一问一答；问菜单会自动触发 MenuTool 工具调用 */
    public String chat(String message) {
        try {
            return chatClient.prompt()
                    .user(message)
                    .call()
                    .content();
        } catch (Exception e) {
            // 无 Key/网络不通/额度用尽——统一转成友好提示，不让异常栈吓到顾客
            throw new BusinessException(ErrorCodeEnum.AI_SERVICE_ERROR);
        }
    }

    /**
     * AI 点单（第18课核心）：自然语言 → OrderRequest → 直接走第9课的收银台。
     * 结构化输出 .entity(OrderRequest.class)：框架自动在提示词里附上目标 JSON 结构，
     * 模型照格式输出，框架再反序列化成对象——前后端第2课定的契约，AI 也照办。
     */
    public OrderVO orderByAi(String message) {
        OrderRequest request;
        try {
            request = orderParser.prompt()
                    .user(message)
                    .call()
                    .entity(OrderRequest.class);
        } catch (Exception e) {
            throw new BusinessException(ErrorCodeEnum.AI_SERVICE_ERROR);
        }
        if (request == null || request.getDishList() == null || request.getDishList().isEmpty()) {
            // 识别不出菜品：AI 的"幻觉"被第6课+第8课的业务校验兜住
            throw new BusinessException(ErrorCodeEnum.DISH_NOT_FOUND);
        }
        // 关键一行：AI 只是新的"入口"，下单仍是老收银台——
        // 事务、价格快照、订单记名（第9/11/16课）全部原样生效
        return orderService.createOrder(request);
    }
}
```

慢慢品这几处：

- **`clone()` 出两个 ChatClient**：Builder 是"配方"，clone 一份改人设，互不污染——聊天的小智要热情，解析器要冷冰冰只出 JSON，一个脑子干不了两件事。注意小智的人设里加了新要求："先调用工具查真实菜单再回答，不要凭空编造"——配合 `defaultTools(menuTool)`，治幻觉的方子。
- **`.entity(OrderRequest.class)`**：结构化输出的全部用法就这一行。框架做的事：把 OrderRequest 的字段结构（dishList→dishName/count）翻译成提示词要求 → 模型输出纯 JSON → 反序列化成对象。
- **空 dishList 防线**：解析器被告知"识别不出就输出空列表"，我们在这里翻译成 40401。
- **最后一行 `orderService.createOrder(request)`**：AI 点单的"落点"是第 9 课的收银台——事务、价格快照、订单记名（第 16 课的 `UserContext.require()`）全部自动生效。**AI 没有特权，也不需要特权。**

## Step 3：AiController 加下单接口（5 分钟）

`controller/AiController.java` 追加（import 补 `OrderVO`）：

```java
    // AI 帮你下单：说句话就行——"来份不辣的下饭菜"
    @PostMapping("/order/ai")
    public Result<OrderVO> orderByAi(@RequestBody ChatRequest req) {
        return Result.success(aiService.orderByAi(req.getMessage()));
    }
}
```

**路径讲究**：为什么不叫 `/ai/order` 而叫 `/order/ai`？——第 16 课拦截器的规则是 `addPathPatterns("/order/**")`：**AI 下单也在 /order/ 下，自动被查票员罩住**。动真格花钱的事，AI 入口和人工入口同一规矩。换个路径前缀就要改拦截规则——URL 也是架构。

## Step 4：前端"帮我下单"按钮（10 分钟）

`index.html` 两处：

**① AI 区的按钮旁加一个红色的**：

```html
        <button class="ai-btn" onclick="askAi()">问小智</button>
        <button class="ai-btn" style="background:#c0392b" onclick="orderAi()">帮我下单</button>
```

**② script 里 askAi 之后加函数**：

```js
    // 第18课：让小智帮你下单——说句话即可（要已登录：AI 下单也要亮卡）
    function orderAi() {
        const msg = aiInput.value.trim();
        if (!msg) { alert('告诉小智你想吃什么'); return; }
        aiReply.textContent = '小智下单中…';
        fetch('/order/ai', {
            method: 'POST',
            headers: authHeaders(),
            body: JSON.stringify({ message: msg })
        })
        .then(r => r.json())
        .then(result => {
            aiReply.textContent = result.code === 200
                ? '✅ ' + result.data.msg + '\n' + JSON.stringify(result.data, null, 2)
                : '❌ ' + result.msg + '（code=' + result.code + '）';
        });
    }
```

前端第七次联动：`authHeaders()` 带卡——AI 下单也要亮卡（和你自己下单同一个函数）。

## Step 5：重启验证

重启后按下一文件清单逐项验证。没有 Key 的话，两个 AI 接口都应返回 50002（降级），其余全部正常——这同样是有效验证。

> **常见报错**
>
> | 现象 | 原因 | 解法 |
> |---|---|---|
> | `/order/ai` 返回 40101 | 没登录/没带卡 | **这是对的**——AI 下单也要亮卡 |
> | 18.1 返回 40401 但话里有菜 | 解析器输出的菜名和菜单不一致 | 看服务端日志/优化解析器提示词 |
> | 工具没被调用（编造菜单） | 人设里没写"先查工具" | 对照 Step 2 的系统提示词 |
