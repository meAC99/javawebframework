# 第1课 · 动手做：从 start.spring.io 到"本店开业"

共 6 步。骨架由 **Spring Initializr**（start.spring.io）生成——杂活让工具干，你只写业务代码。本课你真正"写"的只有一个接口和一个配置文件。

## Step 1：用 Spring Initializr 生成项目骨架（10 分钟）

打开浏览器访问 **https://start.spring.io**，按下面填：

| 项 | 填什么 | 说明 |
|---|---|---|
| Project | **Maven** | 我们用 Maven 管依赖 |
| Language | **Java** | |
| Spring Boot | **4.1.1** | 课程统一版本 |
| Group | **com.cdutetc** | 学院域名倒写 |
| Artifact | **nanpo-xiaochao** | 项目名 |
| Packaging | **Jar** | 内嵌 Tomcat，一个 jar 就是一个店 |
| Java | **17** | |

再点 **Options** 展开高级选项：

| 项 | 填什么 | 说明 |
|---|---|---|
| Name | **nanpo** | 它决定启动类的名字：NanpoApplication |
| Description | 南坡小炒——课程主线项目 | |
| Package name | **com.cdutetc.nanpo** | 一般自动生成，确认即可 |

添加依赖（左上 ADD DEPENDENCIES 或 Ctrl/Cmd+B，搜名字）：

- **Spring Web**——注意：Boot 4 里它实际引入的依赖叫 `spring-boot-starter-webmvc`（老教程叫 starter-web，是历史版本）
- **Lombok**——自动生成 getter/setter 等样板代码

点最下方 **GENERATE**，下载得到 `nanpo-xiaochao.zip`，解压到你的工作目录（比如 `~/temp/`），然后用 IDEA **Open** 打开这个目录。首次打开 IDEA 会下载依赖，等右下角进度条走完。

**看一眼 Initializr 替你生成了什么**：

```
nanpo-xiaochao/
├── .gitignore                 ← 已帮你配好（target/、.idea/ 等都在忽略列表里）
├── pom.xml                    ← 装修合同（Step 2 逐块看懂）
├── mvnw / mvnw.cmd / .mvn/    ← Maven 包装器：没装 Maven 也能构建，且全班同一版本
└── src/
    ├── main/
    │   ├── java/com/cdutetc/nanpo/NanpoApplication.java   ← 启动类（Step 3）
    │   └── resources/application.properties                ← 配置文件（Step 4 换成 yml）
    └── test/java/com/cdutetc/nanpo/...                     ← 测试（本课不用动）
```

> **坑**：如果 ADD DEPENDENCIES 搜不到某依赖，检查 Spring Boot 版本是否选了 4.1.1；版本选错还会导致后面生成的 pom 和课程不一致。

## Step 2：看懂 pom.xml——你签的装修合同（15 分钟）

打开 Initializr 生成的 `pom.xml`，逐块对照（内容应基本一致，顺序/注释略有差异没关系）：

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>4.1.1</version>
    <relativePath/>
</parent>
<groupId>com.cdutetc</groupId>
<artifactId>nanpo-xiaochao</artifactId>
<version>0.0.1-SNAPSHOT</version>
<name>nanpo</name>
<description>南坡小炒——课程主线项目</description>

<properties>
    <java.version>17</java.version>
</properties>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc</artifactId>  <!-- Spring Web -->
    </dependency>
    <dependency>
        <groupId>org.projectlombok</groupId>
        <artifactId>lombok</artifactId>
        <optional>true</optional>
    </dependency>
    <dependency> <!-- 测试套装，scope=test 只在测试时生效 -->
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-webmvc-test</artifactId>
        <scope>test</scope>
    </dependency>
</dependencies>
```

逐块理解：

- **`<parent>`**：继承 `spring-boot-starter-parent` 4.1.1。从这一刻起，几百个常用依赖库的版本号都有了"官方推荐值"，你后面引依赖**全都不用写版本**。这是约定优于配置的第一口甜头。
- **`spring-boot-starter-webmvc`**：本课主角。一个 starter 拖来一整车：内嵌 Tomcat（不用自己装服务器）、Spring MVC（处理 HTTP）、Jackson（对象↔JSON 互转）。这就是"半成品套装"。
- **`lombok`**：编译期工具，帮你生成样板代码，下节课第一次见效。`optional=true` 表示不传染给依赖你的人。
- **版本号一个都没写**——parent 管着。以后引依赖也不写版本；有版本冲突，先怀疑自己抄了旧教程。

## Step 3：认识启动类——营业执照（10 分钟）

Initializr 已生成 `src/main/java/com/cdutetc/nanpo/NanpoApplication.java`（所以 Step 1 的 Name 要填 `nanpo`——名字就是从它来的）：

```java
package com.cdutetc.nanpo;

import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;

@SpringBootApplication
public class NanpoApplication {

	public static void main(String[] args) {
		SpringApplication.run(NanpoApplication.class, args);
	}

}
```

**`@SpringBootApplication` 是三合一**（IDEA 里按住 Ctrl 点进去看，它头上顶着三个注解）：

1. `@SpringBootConfiguration`——本类是一个配置类
2. `@EnableAutoConfiguration`——**自动配置开关**：Spring Boot 检查你引了什么依赖，自动装配对应组件（你引了 webmvc，它就装配 Tomcat 和 MVC）
3. `@ComponentScan`——扫描本类所在包及子包，发现带注解的组件（第 3、4 课的主角）

**位置很重要**：它必须放在**最外层的包**（`com.cdutetc.nanpo`），否则别的包扫不到。这也解释了为什么你以后的代码都建在 `com.cdutetc.nanpo` 底下。

## Step 4：配置文件——从 properties 换成 yml（5 分钟）

Initializr 生成的是 `application.properties`（`spring.application.name=nanpo` 这种格式）。课程统一用 **yml**：删掉 `application.properties`，同目录新建 `application.yml`：

```yaml
spring:
  application:
    name: nanpo-xiaochao

server:
  port: 8080
```

**为什么**：yml 层级缩进，比 properties 的平铺键直观得多，是 Spring Boot 官方推荐。注意**用空格缩进，不能用 Tab**——Tab 直接报解析错误，是新手第一大坑。

以后数据库、文件上传、JWT 密钥……所有配置都会住进这个文件，它是你店的"公告栏"。

## Step 5：写你的第一段代码——挂牌营业（15 分钟）

创建 `src/main/java/com/cdutetc/nanpo/controller/HelloController.java`（先建 `controller` 包）。**这是这门课你亲手敲的第一段业务代码**：

```java
package com.cdutetc.nanpo.controller;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RestController;

/**
 * 第1课验证接口：店开了没有？
 * 浏览器或 REST Client 访问 http://localhost:8080/hello
 */
@RestController
public class HelloController {

    @GetMapping("/hello")
    public String hello() {
        return "南坡小炒，本店开业！";
    }
}
```

两个注解各司其职：

- `@RestController`：告诉 Spring"这个类是接待 HTTP 请求的窗口，方法的返回值直接写进响应体"。（它是 `@Controller` + `@ResponseBody` 的合体，后者表示"返回值不是网页模板，而是数据本身"）
- `@GetMapping("/hello")`：注册一条路由——GET 方式访问 `/hello` 的请求，交给 `hello()` 方法处理。返回的 String 由 Spring 原样写回浏览器。

## Step 6：启动！学会看日志（10 分钟）

命令行启动（也可以在 IDEA 里直接运行 `NanpoApplication`）：

```bash
./mvnw spring-boot:run
```

第一次要下载依赖，等一两分钟。看到这两行就是**开业成功**：

```
Tomcat started on port 8080 (http) with context path '/'
Started NanpoApplication in x.xxx seconds
```

**学会读启动日志**：现在才十几行，以后出问题 90% 靠它。`Started ...` 就是"启动完成"；启动失败时，从上往下找第一行 `ERROR` 或异常名。

停掉程序：终端按 `Ctrl + C`。

> **常见报错速查**
>
> | 现象 | 原因 | 解法 |
> |---|---|---|
> | `Port 8080 was already in use` | 8080 被占（多半上次没停） | 停掉旧进程，或 Step 4 把 port 改 8081 |
> | yml 解析错误（`while scanning...`） | 用了 Tab 缩进 | 全部换空格 |
> | 下载依赖卡住/超时 | 网络 | 重试；IDEA 可配置国内镜像源 |
> | `class file has wrong version` | JDK 版本不对 | `java -version` 确认 17+ |
> | 找不到 `./mvnw` | 不在项目根目录 | 先 `cd nanpo-xiaochao` |
