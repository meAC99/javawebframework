# 第8课 · 动手做：菜谱大搬家（entity → dao → 初始化 → 接口改造）

共 6 步。本课新增 3 个类、改造 3 个类、**删除** 1 段代码——大搬家的完整动作。

## Step 1：第一个实体 Menu（20 分钟）

新建包 `com.cdutetc.nanpo.entity`，创建 `entity/Menu.java`：

```java
package com.cdutetc.nanpo.entity;

import java.math.BigDecimal;

import jakarta.persistence.Column;
import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

import lombok.Data;
import lombok.NoArgsConstructor;

/**
 * 菜单实体——数据库表 t_menu 在 Java 里的"影子"：一个字段对应一列。
 * 第8课：菜谱从 WaiterController 的静态 Map 搬进数据库，改价不用再改代码发版。
 * 目录规范：实体（表）放 entity 包，操作表的手（Repository）放 dao 包。
 */
@Entity
@Table(name = "t_menu")
@Data
@NoArgsConstructor      // JPA 要求：反射创建对象时需要无参构造
public class Menu {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)   // 主键自增
    private Long id;

    @Column(nullable = false)
    private String dishName;

    @Column(nullable = false)
    private BigDecimal price;   // 钱一律 BigDecimal——第2课用 Integer 是教学起点的妥协，本次一并整改

    // 不用 @AllArgsConstructor：它会把 id 也算进去生成三参构造器，初始化用不上；
    // 手写两参构造器，id 留给数据库自增
    public Menu(String dishName, BigDecimal price) {
        this.dishName = dishName;
        this.price = price;
    }
}
```

注解逐个看懂：

- `@Entity`：宣布"这个类是数据库表的影子"，启动时 Hibernate 会拿它对照建表。
- `@Table(name = "t_menu")`：对应的表名。不加就默认用类名 `Menu`；加前缀 `t_` 是很多团队的表命名规范，也避开和关键字撞车。
- `@Id` + `@GeneratedValue(IDENTITY)`：主键 + 数据库自增——id 永远不用你操心。
- `@Column(nullable = false)`：这一列非空，建表时自动带上 NOT NULL 约束。
- `@Data` 但构造器手写：见下方"真实踩坑"。

> **真实踩坑（本课开发者亲自踩过）**：一开始想偷懒用 `@AllArgsConstructor`，结果初始化代码 `new Menu("回锅肉", price)` 编译报错——**lombok 的全参构造器把 `id` 也算进去了，生成的是三参构造器**。教训：注解省事但不总贴心，实体里手写"业务用得上"的构造器更稳。

## Step 2：MenuRepository——不写 SQL 的查询（15 分钟）

新建包 `com.cdutetc.nanpo.dao`，创建 `dao/MenuRepository.java`：

```java
package com.cdutetc.nanpo.dao;

import java.util.Optional;

import org.springframework.data.jpa.repository.JpaRepository;

import com.cdutetc.nanpo.entity.Menu;

/**
 * 菜单的数据访问接口——操作 t_menu 的"手"。
 * 零实现类：Spring Data JPA 启动时自动生成；
 * 零 SQL：findByDishName 按方法名规则自动派生查询
 * （select * from t_menu where dish_name = ?）。
 */
public interface MenuRepository extends JpaRepository<Menu, Long> {

    Optional<Menu> findByDishName(String dishName);
}
```

这是 Spring Data JPA 最"魔幻"的一刻，看清楚三件事：

- 你写的是**接口**，没有实现类——启动时框架自动生成实现并注册成 Bean（所以能被 `@Autowired`）。
- `findByDishName(String)` **方法名就是查询**：框架解析方法名，翻译成 `where dish_name = ?`。想按价格查就写 `findByPrice(...)`，见名知义。
- 继承 `JpaRepository<Menu, Long>` 白得一堆现成方法：`findAll()`、`save()`、`count()`、`findById()`……后面课程反复用。

`Optional` 的含义：查到的可能是"没有"——返回 `Optional<Menu>` 强迫你处理"查无此菜"的情况，下一节正好接上第 6 课的业务异常。

## Step 3：开市准备——MenuDataInitializer（15 分钟）

新建包 `com.cdutetc.nanpo.config`，创建 `config/MenuDataInitializer.java`：

```java
package com.cdutetc.nanpo.config;

import java.math.BigDecimal;

import org.springframework.boot.CommandLineRunner;
import org.springframework.stereotype.Component;

import com.cdutetc.nanpo.dao.MenuRepository;
import com.cdutetc.nanpo.entity.Menu;

/**
 * 开市前的准备：把初始菜单装进数据库。
 * 时机：CommandLineRunner——容器启动完成、表已建好之后自动执行。
 * 幂等：先 count() 判断，已有数据就不重复插（第19课换 MySQL 重启时菜单不会翻倍）。
 */
@Component
public class MenuDataInitializer implements CommandLineRunner {

    // 推荐写法：构造器注入（字段可 final；单构造器时可省 @Autowired）
    private final MenuRepository menuRepository;

    public MenuDataInitializer(MenuRepository menuRepository) {
        this.menuRepository = menuRepository;
    }

    @Override
    public void run(String... args) {
        if (menuRepository.count() > 0) {
            return;
        }
        menuRepository.save(new Menu("回锅肉", new BigDecimal("18")));
        menuRepository.save(new Menu("鱼香肉丝", new BigDecimal("16")));
        menuRepository.save(new Menu("麻婆豆腐", new BigDecimal("12")));
        menuRepository.save(new Menu("番茄炒蛋", new BigDecimal("10")));
        menuRepository.save(new Menu("蛋炒饭", new BigDecimal("8")));
        menuRepository.save(new Menu("米饭", new BigDecimal("1")));
    }
}
```

三个关键点：

- **时机**：`CommandLineRunner` 的 `run()` 在容器启动完成、**表已建好之后**自动执行——顺序由框架保证（第 4 课"员工报到"日志的近亲，再往前一步）。
- **幂等**：`count() > 0` 就返回。现在内存库每次重启都是空的，看不出作用；但第 19 课换 MySQL 后重启，没有这行菜单就会翻倍成 12 道、18 道……幂等是"以后的我"感谢"现在的我"的代码。
- **构造器注入**：第 4 课你学了字段注入 `@Autowired`，这里是更被推崇的写法——字段能 `final`、依赖一目了然，单构造器连 `@Autowired` 都能省。以后新代码推荐这种。

## Step 4：服务员大手术——删静态菜单，改查数据库（20 分钟）

改 `WaiterController.java`，动作最大的一步：

**① 整段删除 static 菜谱**（第 2 课活到现在的 static 块），原位置留注释：

```java
    // 第8课：从第2课用到现在的静态 MENU Map 已删除——菜单的唯一权威来源是 t_menu 表，
    // 改价只需 update 数据库，再也不用改代码重新发版
```

**② 注入 MenuRepository**（和原有的两个服务注入放一起）：

```java
    @Autowired
    private MenuRepository menuRepository;
```

**③ /menu 改查库**（对外仍是 `Map{菜名:价格}` 形状，前端零改动）：

```java
    // 查菜单：第8课整改——数据来源换成 t_menu 表。
    // 对外仍保持 Map{菜名:价格} 的形状，前端零改动：换数据源，不动对外契约
    @GetMapping("/menu")
    public Result<Map<String, BigDecimal>> getMenu() {
        Map<String, BigDecimal> menu = new LinkedHashMap<>();
        menuRepository.findAll().forEach(m -> menu.put(m.getDishName(), m.getPrice()));
        return Result.success(menu);
    }
```

**④ /order 验菜取价改走数据库**——循环里原来"查 Map"的两段，换成：

```java
            // 第8课整改：验菜+取价一步完成——查 t_menu，
            // 查不到就抛业务异常（第6课的处理台会转成规范小票）
            Menu menu = menuRepository.findByDishName(dishName)
                    .orElseThrow(() -> new BusinessException(ErrorCodeEnum.DISH_NOT_FOUND));

            BigDecimal subTotal = menu.getPrice().multiply(BigDecimal.valueOf(count));
            total = total.add(subTotal);
```

金额全部 BigDecimal 化：`total` 声明改为 `BigDecimal total = BigDecimal.ZERO;`，`OrderItem` 的 setUnitPrice/setSubTotal 传 `menu.getPrice()` 和 `subTotal`。

补 import：`java.math.BigDecimal`、`java.util.LinkedHashMap`、`com.cdutetc.nanpo.dao.MenuRepository`、`com.cdutetc.nanpo.entity.Menu`。类头注释追加：

```java
 * 第8课：菜谱上账——静态 MENU Map 彻底删除，验菜取价全部查数据库 t_menu。
```

> 注意 `LinkedHashMap`：普通 HashMap 不保证顺序（第 2 课验证时你见过乱的菜单），Linked 保留插入顺序——而插入顺序来自 `findAll()`，下次数据库课你会看到它按什么排。

## Step 6：重启，看"透视眼"（10 分钟）

```bash
./mvnw spring-boot:run
```

启动日志里找 show-sql 的证据（节选）：

```
Hibernate: create table t_menu (...)
Hibernate: insert into t_menu (dish_name,price,id) values (?,?,default)
...（共 6 条 insert）
```

读这行 insert 有个小门道：`id` 列排在最后且值是 `default`——因为主键是 IDENTITY 自增，**id 不由程序填，由数据库自己发号**。

然后登录 h2-console，左侧树刷新——`T_MENU` 出现了，里面躺着 6 行账。**第 7 课的空账本，从此有第一页了。**

> **常见报错**
>
> | 现象 | 原因 | 解法 |
> |---|---|---|
> | 启动报 `找不到符号 MenuRepository` | dao 包建错位置/没继承 JpaRepository | 对照 Step 2 检查包名 |
> | `Syntax error` 在 /order | total 忘了改 BigDecimal 声明 | `BigDecimal total = BigDecimal.ZERO` |
> | h2-console 看不到表 | 没刷新 / 登录的库名不对 | 刷新左侧树；确认 jdbc:h2:mem:nanpo |
