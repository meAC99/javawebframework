# 第8课 · 验证、提交与练习

## 一、验证清单（全过才算下课）

本课**不新增请求**——重放老请求看"输出变化"，这正是"换数据源、不动契约"的证明方式。

**1. 重放 2.1 查菜单——价格变成两位小数**

预期（对照第 7 课的 `18`，现在是 `18.00`——BigDecimal + DECIMAL 的标准长相）：

```json
{"code":200,"data":{"回锅肉":18.00,"鱼香肉丝":16.00,"麻婆豆腐":12.00,"番茄炒蛋":10.00,"蛋炒饭":8.00,"米饭":1.00},"msg":"操作成功"}
```

顺带注意：菜的顺序**稳定**了（LinkedHashMap 的功劳，第 2 课的乱序问题顺手解决）。终端同时打出 `select ... from t_menu`——**菜单确实来自数据库**。

**2. 重放 2.2 正常点单**

预期：金额两位小数、总额不变，`"totalMoney":38.00`；终端能看到 `select ... from t_menu where dish_name=?`（验菜查询）。

**3. 重放 6.1 佛跳墙**

预期仍是 `{code:40401}`——但它的实现变了：以前查 Map，现在是查库 `findByDishName` 返回空 `Optional`，`orElseThrow` 抛异常。同一个错误码，两种人生。

**4. 终极验证：改价不用发版**

登录 h2-console，执行：

```sql
UPDATE T_MENU SET PRICE = 20 WHERE DISH_NAME = '回锅肉';
```

回到 REST Client 重放 2.1——回锅肉变 `20.00` 了。**你没改一行代码、没重启服务**，第 6 课老板的吐槽（"涨两块钱要等你发版"）正式结案。做完把价格改回 18，免得后面课的验证对不上数。

**5. 浏览器回归**：点餐页菜单正常（价格显示 ￥18.00）、下单正常。

## 三、课后练习

1. **菜单自选动作**：在 `MenuDataInitializer` 里加一道你的拿手菜，重启后 h2-console 和 `/menu` 都能看到（注意 H2 内存库重启清零，所以"加菜"要写在初始化里才每次都在）。
2. **试试派生查询的威力**：给 `MenuRepository` 加一个 `List<Menu> findByPriceLessThan(BigDecimal price)`，写个临时接口调用它，请求"10 元以下的菜"。做完删掉临时代码。
3. **思考题**：`findByDishName` 返回 `Optional<Menu>` 而不是 `Menu` 或 `null`——这样设计的好处是什么？（提示：第 6 课的 `orElseThrow` 为什么能一行接上？）

## 四、下一课预告

菜单有账了，可订单还是"打完小票就扔"——`/order` 算完总额返回之后什么都不留，重启全没、老板对不了账、也没法查"今天卖了多少回锅肉"。

下一课给订单建账：一张订单多个菜，怎么设计表？（剧透：订单本 + 订单明细两本账，一对多。）你还会遇到本课程最经典的命名冲突——**实体 OrderItem 和小票 OrderItem 同名打架**，这个别扭将逼出再下一课的"小票与账本分离"。另外，第 2 课以来一直背着全部业务的服务员，也终于要把活交给一位新角色：收银台 `OrderService`。
