## 上一课发生了什么

账本（H2 数据库）建好了，h2-console 也能登录了——但翻开一看，`PUBLIC` 下面空空如也：`ddl-auto` 只按**实体**建表，而你还没有任何实体。与此同时，菜谱还写死在 `WaiterController` 的 static 块里，第 6 课老板那句"改个价要重新发版"的吐槽还悬着。

今天办一场**大搬家**：菜谱从 Java 代码搬进数据库。搬完之后——

- 启动时 `t_menu` 表自动出现，6 道菜自动入库
- 菜单接口直接查库，前端看到的还是那 6 道菜（对外零变化，数据来源彻底换了）
- **改价 = 在 h2-console 里执行一句 UPDATE，不用碰一行代码**——本课的终极验证

## 本课你将学会

1. JPA 实体注解族：`@Entity/@Table/@Id/@GeneratedValue/@Column`
2. Spring Data JPA 的"魔法"：`MenuRepository` 接口不写实现、不写 SQL，方法名就是查询
3. `CommandLineRunner`：容器启动完成后自动执行初始化，幂等保护怎么写
4. 钱为什么必须用 `BigDecimal` 而不是 double/int
5. 项目目录规范升级：`entity` 包放"表"，`dao` 包放"操作表的手"

## 先想清楚：钱为什么不能用 double？

在 Java 里跑一句 `System.out.println(0.1 + 0.2)`，你会得到 `0.30000000000000004`——不是 Java 有 bug，是 **double 的二进制浮点天生表示不了 0.1**（就像十进制写不尽 1/3）。日常计算无所谓，但金额差一分钱都是事故。

所以本课在把菜价搬进数据库的同时，把第 2 课用 `Integer` 存价格的"教学起点妥协"一并整改：**钱的字段，从实体到小票，全部换成 `BigDecimal`**。你会看到菜单价格从 `18` 变成 `18.00`——那是 DECIMAL 两位小数的标准长相。
