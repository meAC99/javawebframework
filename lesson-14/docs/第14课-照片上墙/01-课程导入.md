# 第14课 · 课程导入：照片上墙

## 上一课发生了什么

照片能传了：UUID 命名、落在 `upload/` 目录、路径写进了 `t_menu`。但访问 `/files/xxx.png` 得到的是 40404——Spring Boot 的静态资源约定只认 `static/`、`public/` 那几个目录，你的 `upload/` 不在名单里。

今天把这堵墙拆掉，让照片真正"上墙"。四个任务串成一条线：

```
① 配静态资源映射        /files/** → upload/ 目录（浏览器直接"看"照片）
② 写下载接口            /download/{filename}（浏览器"另存为"照片）
③ 上传大小限制闭环       2MB 上限 + 超限异常接进第6课处理台
④ 菜单出参升级 MenuVO    Map 装不下 imageUrl 了 → 前端真的显示图片
```

## 先想清楚一：直接看 vs 下载，差在哪？

浏览器访问 `http://localhost:8080/files/xxx.png`，照片直接显示在页面上；访问 `http://localhost:8080/download/xxx.png`，浏览器弹出"另存为"。**同一个文件、两种行为，差别只在一个响应头**：

```
Content-Disposition: attachment; filename="xxx.png"     ← 附件（下载另存为）
Content-Disposition: inline                            ← 内联（直接打开/显示）
（不写这个头，浏览器按 Content-Type 自己猜——图片就显示）
```

一个响应头改变浏览器行为——HTTP 报文的细节，第一次这么直观。

## 先想清楚二：/download/../pom.xml 会发生什么？

下载接口的参数是文件名，用户可以**随便填**。如果接口直接拼路径 `upload/` + 用户输入，那么 `../pom.xml` 就能下载你项目里的任意文件——这叫**路径穿越攻击**。

防御思路一句话：用户给的路径**解析（normalize）之后必须还在 upload 目录里**，否则一律当作"文件不存在"拒绝。本课代码里两行防御，外加 Tomcat 在 URL 层的第一道拦截——你会实测看到**两层防线各拦一次**。

## 本课你将学会

1. `@Configuration` + `WebMvcConfigurer` 自定义静态资源映射（以及"目录型 location 必须以 / 结尾"的坑）

5. 菜单出参 VO 化（Map → List\<MenuVO\>）+ 前端图片渲染
