# 第14课 · 动手做：资源映射 · 下载 · 超限闭环 · 菜单带图

共 6 步。第 1 步一完成，上一课的 40404 钩子立刻兑现。

## Step 1：WebMvcConfig——给 /files/** 指路（15 分钟）

新建 `config/WebMvcConfig.java`——项目里**第一个正式的 @Configuration 配置类**（第 4 课口头预告过的角色终于登场）：

```java
package com.cdutetc.nanpo.config;

import java.nio.file.Path;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.ResourceHandlerRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

/**
 * Spring MVC 配置（第14课）。
 * 项目里第一个正式的 @Configuration 类——把 /files/** 映射到本地上传目录，
 * 浏览器就能直接访问照片（第1课讲过的静态资源约定的"手动版"）。
 */
@Configuration
public class WebMvcConfig implements WebMvcConfigurer {

    private final StorageProperties storageProperties;

    public WebMvcConfig(StorageProperties storageProperties) {
        this.storageProperties = storageProperties;
    }

    @Override
    public void addResourceHandlers(ResourceHandlerRegistry registry) {
        // 坑：目录型 resource location 必须以 / 结尾，否则映射不生效
        String location = Path.of(storageProperties.getDir())
                .toAbsolutePath().normalize().toUri().toString();
        if (!location.endsWith("/")) {
            location += "/";
        }
        registry.addResourceHandler("/files/**")
                .addResourceLocations(location);
    }
}
```

看懂三个点：

- **`WebMvcConfigurer` + 重写方法**：Spring MVC 的官方扩展口——不动默认行为，只"追加"你的配置。`addResourceHandlers` 专管静态资源映射。
- **对照第 1 课**：那时说"文件放 static/ 自动被服务"是**约定**；今天是自己动手注册映射——**约定的手动版**，原理此刻打通。
- **注释里那个坑是真的**：`addResourceLocations` 的目录地址必须以 `/` 结尾（`file:///xxx/upload/`），少了斜杠整个映射静默失效——不报错、就是 404，排查半小时起步的坑，提前写进注释。

**立刻验证**：重启程序，发送上一课留下的钩子请求 `GET /files/<你的uuid>.png`——

预期：状态码 `200`，响应头 `Content-Type: image/png`，响应体是图片二进制（REST Client 面板里会显示图片预览）。**上一课的 40404 就地兑现。** 浏览器地址栏直接贴这个 URL，照片直接显示。

## Step 2：下载接口——Content-Disposition 的力量（20 分钟）

`KitchenController` 补一个下载端点（追加字段注入和方法，import 补 `Files/Path/FileSystemResource/Resource/HttpHeaders/MediaType/ResponseEntity/GetMapping/StorageProperties`）：

```java
    @Autowired
    private StorageProperties storageProperties;

    // 下载文件：和 /files/** 直接访问的区别——
    // Content-Disposition: attachment 让浏览器弹出"另存为"而不是直接打开
    @GetMapping("/download/{filename}")
    public ResponseEntity<Resource> download(@PathVariable String filename) {
        Path root = Path.of(storageProperties.getDir()).toAbsolutePath().normalize();
        Path path = root.resolve(filename).normalize();

        // 防路径穿越：/download/../pom.xml 之类必须被拦下——
        // 解析后的路径必须仍然位于上传目录内
        if (!path.startsWith(root) || !Files.exists(path)) {
            throw new BusinessException(ErrorCodeEnum.FILE_NOT_FOUND);
        }

        return ResponseEntity.ok()
                .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"" + filename + "\"")
                .contentType(MediaType.APPLICATION_OCTET_STREAM)
                .body(new FileSystemResource(path));
    }
```

（`ErrorCodeEnum.FILE_NOT_FOUND(40405, "文件不存在")` 这就去加——见 Step 3 一起。）

逐块看懂：

- **返回类型变了**：前 13 课的接口返回 `Result<T>`（业务数据）；这个接口返回的是**文件本身**（二进制流），用 `ResponseEntity<Resource>`——从状态码、响应头到响应体全由你手工控制。这是第 6 课思考题"想让状态码语义化"的正牌工具。
- **防御两连**：`root.resolve(filename).normalize()` 把用户输入拼进根目录并展开（`../` 会被消掉），然后 `path.startsWith(root)` 检查展开后是否还待在 upload 里——`../pom.xml` 展开后跑到根目录外，当场拒绝。
- `APPLICATION_OCTET_STREAM`（任意二进制流）：告诉浏览器"别试图打开它"。

## Step 3：上传大小限制闭环（15 分钟）

三处小改，兑现第 6 课"新异常随时接入处理台"的承诺：

**① `application.yml`** 的 `spring:` 段里加（注意缩进层级，与 datasource/jpa 平级）：

```yaml
  # 第14课：上传大小限制——超限在 multipart 解析阶段就被拒绝，
  # MaxUploadSizeExceededException 由第6课的统一异常处理台接住
  servlet:
    multipart:
      max-file-size: 2MB
      max-request-size: 2MB
```

**② `ErrorCodeEnum`** 的 4xxxx 区追加两个词：

```java
    FILE_NOT_FOUND(40405, "文件不存在"),           // 下载接口用
    FILE_TOO_LARGE(40406, "上传文件超过大小限制（最大 2MB）"),
```

**③ `GlobalExceptionHandler`** 在路径不存在分支之后、系统异常兜底之前追加：

```java
    // 第14课兑现第6课的承诺：上传超限异常接入处理台——
    // multipart 解析阶段就拒绝，根本到不了 Controller
    @ExceptionHandler(MaxUploadSizeExceededException.class)
    public Result<?> handleMaxUploadSize(MaxUploadSizeExceededException e) {
        log.warn("上传文件超过大小限制: {}", e.getMessage());
        return Result.fail(ErrorCodeEnum.FILE_TOO_LARGE);
    }
```

（import `org.springframework.web.multipart.MaxUploadSizeExceededException`。）

**闭环的关键认知**：文件超限时异常发生在 **multipart 解析阶段**——请求还没到 Controller，`uploadImage` 根本没执行。所以 Controller 里写校验是拦不到的，必须在处理台接住它。三个分支（业务 40403 / 路径 40404 / 超限 40406）各就各位。

## Step 4：菜单出参升级——Map 装不下照片了（15 分钟）

问题：`/menu` 现在返回 `Map{菜名:价格}`——**Map 里塞不进 imageUrl**（一个菜三个属性，Map 只有一个键）。第 10 课的 VO 思想再次救场。

**① 新建 `vo/MenuVO.java`**：

```java
package com.cdutetc.nanpo.vo;

import java.math.BigDecimal;

import com.cdutetc.nanpo.entity.Menu;

import lombok.Data;

/**
 * 菜单 VO（第14课新增）。
 * 旧 /menu 返回 Map{菜名:价格}——加了 imageUrl 后 Map 装不下了，
 * 第10课的 VO 思想再次救场：出参按前端需要定义形状。
 */
@Data
public class MenuVO {

    private Long id;
    private String dishName;
    private BigDecimal price;
    private String imageUrl;

    public static MenuVO from(Menu menu) {
        MenuVO vo = new MenuVO();
        vo.setId(menu.getId());
        vo.setDishName(menu.getDishName());
        vo.setPrice(menu.getPrice());
        vo.setImageUrl(menu.getImageUrl());
        return vo;
    }
}
```

**② `WaiterController` 的 /menu 整个换掉**（import 换成 `List/MenuVO`，`BigDecimal/LinkedHashMap/Map` 若不再使用可一并清理）：

```java
    // 查菜单：第14课整改——加了 imageUrl 后 Map{菜名:价格} 装不下了，
    // 出参升级为 List<MenuVO>（前端同步适配，第四次前后端联动）
    @GetMapping("/menu")
    public Result<List<MenuVO>> getMenu() {
        return Result.success(menuRepository.findAll().stream().map(MenuVO::from).toList());
    }
```

## Step 5：前端渲染图片（15 分钟）

`index.html` 两处：

**① CSS 加两条**（放在 `.price` 那条附近）：

```css
        .dish img { width: 48px; height: 48px; object-fit: cover; border-radius: 6px; vertical-align: middle; margin-right: 6px; }
        .placeholder { display: inline-block; width: 48px; height: 48px; line-height: 48px; text-align: center; background: #eee; border-radius: 6px; margin-right: 6px; }
```

**② 菜单渲染函数整个换掉**——Map 遍历换成数组遍历，有图显示图、没图显示占位图标：

```js
    // 第14课适配（第四次前后端联动）：/menu 从 Map{菜名:价格} 升级为 List<MenuVO>
    // ——加了 imageUrl 后 Map 装不下了；有照片显示照片，没照片显示占位图标
    fetch('/menu')
        .then(resp => resp.json())
        .then(result => {
            let html = '';
            result.data.forEach(dish => {
                const img = dish.imageUrl
                    ? `<img src="${dish.imageUrl}" alt="${dish.dishName}">`
                    : `<span class="placeholder">🍽️</span>`;
                html += `
                <div class="dish">
                    <span>${img} ${dish.dishName} <span class="price">￥${dish.price}</span></span>
                    <span>数量 <input type="number" min="0" value="0" data-dish="${dish.dishName}"></span>
                </div>`;
            });
            document.getElementById('menu').innerHTML = html;
        });
```

注意 `forEach(dish => ...)`——数据从"Map 键值对"变成"对象数组"，访问方式从解构 `[dishName, price]` 变成 `dish.dishName`。**契约变了前端必须跟**，第 5 课的教训第二次上演（如果你忘了先改前端会怎样——白屏等着你）。
