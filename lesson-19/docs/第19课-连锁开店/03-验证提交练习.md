## 三、本课踩坑实录（都值得抄进笔记）

1. **`Data too long for column 'image_url'`**：MinIO 生成的地址比本地路径长得多，`VARCHAR(255)` 存不下。修：实体 `@Column(length = 1024)`。**但注意**——`ddl-auto: update` 只加列不改列宽，已经建好的表要手动 `ALTER TABLE ... MODIFY`。这正是"update 只配开发环境、生产要上 Flyway/Liquibase 做版本化迁移"的原因。
2. **预签名 URL 暴露内网地址**：直接返回 MinIO 预签名链接的话，浏览器拿到的主机名是容器内部的 `minio:9000`——容器外根本解析不了。修法是本课的架构升级：**图片访问统一走应用端点 `/files/{filename}`**，由 StorageService 决定从磁盘还是 MinIO 取流——浏览器永远只认识你的应用，存储拓扑随便换。
3. **minio 9.x 的 Maven 坑**：9.0.3 依赖 okhttp5/Kotlin 多平台构件，Maven 下类不可见——降到 8.5.x 解决。选依赖不只看版本号新不新，还要看生态配套。

## 五、课后练习

1. **彻底重开一家店**：`docker compose down -v`（连数据卷一起删）再 `up --build`——观察菜单又被幂等初始化自动补齐、照片要重传。体会 `-v` 的分量：**这是删库级操作**。
2. **换端口开业**：把 compose 里 app 的 `"8080:8080"` 改成 `"9090:8080"`——容器内没变，对外换了个门牌（左边是宿主机端口）。`requests.http` 全部改成 9090 试一轮。
3. **思考题**：现在 app 容器里同时起着 H2 相关的配置吗？为什么切 MySQL 后 H2 完全没被用到却也没报错？（提示：驱动按 URL 挑选 + 依赖仍留着给本地开发。如果要做"生产镜像里彻底不带 H2"，Maven 有什么机制？——关键词：profile、optional。）
4. **展望题**：一台机器上 `docker compose up` 是"开店"；一百台机器上保证每台都跑同样的店、坏了自动重开，是什么？（Kubernetes——本课程终点线外的下一站。）
