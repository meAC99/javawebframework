# 第19课 · 课程导入：连锁开店（容器化部署）

## 上一课发生了什么

AI 都能下单了——但整套系统还"住"在你这台电脑上：JDK 17 + 内存数据库 + 本地磁盘。把它交给别的机器（机房、云服务器、同学的笔记本），大概率跑不起来：JDK 版本不对、没有装好的依赖、路径不一样……"**在我电脑上是好的**"是工程师世界最著名的遗言。

今天，把店装进**集装箱**，让它在任何有 Docker 的机器上原样开张。

## 先想清楚：镜像和容器是什么关系？

用开店的比喻一次讲透 Docker 的三个词：

| Docker 概念 | 比喻 | 特点 |
|---|---|---|
| **镜像（Image）** | **标准化的中央厨房配料包** | 只读、可复制——配方固定，拷到哪家分店都一样 |
| **容器（Container）** | **按包开出的一家店** | 运行中的实例——起了停、停了删，删了再开还是那个味 |
| **docker-compose** | **整条街的招商方案** | 一份文件声明"我要 app + MySQL + MinIO 三家店，谁先开、怎么互通" |

而**多阶段构建**：先在"施工容器"里编译打包（带完整 JDK+Maven，个头大），再把**只有 jar 的成品**搬进"营业容器"（只有 JRE，个头小）——施工队不占营业面积。

## 两条暗线，今天兑现

这门课埋的两颗种子，今天同时收割：

**暗线一（第 7-8 课埋）：H2 → MySQL。** H2 是教学用的内存账本（重启清零）；MySQL 是独立持久化的真账本。切换需要改多少代码？**零行**——只靠环境变量覆盖 `SPRING_DATASOURCE_*`（第 15 课起反复用的配置外部化）。菜单哪来？第 8 课写的**幂等初始化**（`count()>0` 就跳过）让 6 道菜在新库自动就位——"以后的我感谢现在的我"，今天就是那个"以后"。

**暗线二（第 13 课埋）：本地磁盘 → MinIO。** `StorageService` 接口有两个实现了，`StorageConfig` 工厂按 `nanpo.storage.type` 装配——compose 里一行 `NANPO_STORAGE_TYPE=minio`，上传的照片就进了对象存储，**KitchenController 一行没改过**。

## 本课你将学会

1. 多阶段 Dockerfile（以及"先拷 pom 再拷代码"的缓存层技巧）
2. docker-compose 编排多容器：healthcheck、启动顺序、数据卷、密钥透传
3. 配置外部化的总验收：换数据库/换存储 = 只改环境变量
4. 两个真实生产坑：数据库列宽不够、容器内外网络拓扑
