共 6 步。前 3 步是代码准备，后 3 步是 Docker 三件套。

## Step 1：pom 加三件依赖（5 分钟）

```xml
		<!-- 第19课：MySQL 驱动——容器化时用环境变量把 H2 换成 MySQL，代码零改动 -->
		<dependency>
			<groupId>com.mysql</groupId>
			<artifactId>mysql-connector-j</artifactId>
			<scope>runtime</scope>
		</dependency>
		<!-- 第19课：MinIO 客户端——StorageService 的对象存储实现。
		     用 8.5.x（okhttp4，Maven 生态最稳）；9.x 依赖 okhttp5/KMP，Maven 下有解析坑 -->
		<dependency>
			<groupId>io.minio</groupId>
			<artifactId>minio</artifactId>
			<version>8.5.17</version>
		</dependency>
		<!-- 第19课：生产就绪——/actuator/health 供 docker-compose 探活 -->
		<dependency>
			<groupId>org.springframework.boot</groupId>
			<artifactId>spring-boot-starter-actuator</artifactId>
		</dependency>
```

- **mysql-connector-j**：版本 Boot BOM 管。`runtime`——代码里永远不 import MySQL 的类，JDBC 在运行时按 URL 自动挑驱动。
- **minio 8.5.17**：版本是本课开发时实测踩坑后的选择——9.0.3 在 Maven 下有 okhttp5 的类可见性问题，8.5.x 稳。
- **actuator**：Spring Boot 的"体检中心"，白送 `/actuator/health` 端点——compose 靠它判断 app 活没活。

**③ `service/StorageService.java` 整体替换**（校验提取为 default 方法 + 新增 load）：

```java
package com.cdutetc.nanpo.service;

import java.util.List;
import java.util.UUID;

import org.springframework.core.io.Resource;
import org.springframework.web.multipart.MultipartFile;

import com.cdutetc.nanpo.common.BusinessException;
import com.cdutetc.nanpo.common.ErrorCodeEnum;

/**
 * 文件存储服务（第13课定义）。
 * 只定义"存文件"这件事怎么做，不关心存在哪——
 * 本地磁盘（LocalStorageService）与 MinIO 对象存储（MinioStorageService，第19课）
 * 是它的两个实现，业务代码面向本接口编程，换实现一行不改。
 * 第19课：公共的校验+改名逻辑提取为 default 方法；
 *         新增 load()——图片访问统一走应用端点 /files/{filename}，
 *         由实现类决定从磁盘还是对象存储取流，浏览器不感知存储拓扑。
 */
public interface StorageService {

    /**
     * 保存文件，返回可访问的 URL 路径（/files/xxx.png）
     */
    String store(MultipartFile file);

    /**
     * 按文件名读取文件（供 /files/{filename} 与 /download/{filename} 端点代理访问）
     */
    Resource load(String filename);

    /**
     * 公共校验与改名（第19课提取）：空文件/扩展名白名单校验，返回 UUID 新文件名。
     * default 方法——接口里带实现，两个实现类直接继承用。
     */
    default String validateAndRename(MultipartFile file) {
        // 校验一：空文件
        if (file == null || file.isEmpty()) {
            throw new BusinessException(ErrorCodeEnum.FILE_INVALID);
        }
        // 校验二：扩展名白名单（教学版按扩展名判；生产要校验文件头/内容类型）
        String original = file.getOriginalFilename();
        String ext = "";
        if (original != null && original.lastIndexOf('.') >= 0) {
            ext = original.substring(original.lastIndexOf('.')).toLowerCase();
        }
        if (!List.of(".jpg", ".jpeg", ".png", ".gif", ".webp").contains(ext)) {
            throw new BusinessException(ErrorCodeEnum.FILE_INVALID);
        }
        // 重名防护：UUID 做新文件名，原文件名只留扩展名
        return UUID.randomUUID() + ext;
    }
}
```

两个新知识：**default 方法**（接口里带实现，两个实现共用，不用再各抄一遍）；**load(filename)**（读取也抽象——马上知道为什么）。

**④ `service/LocalStorageService.java` 整体替换**（去 @Service、用 default 方法、加 load）：

```java
package com.cdutetc.nanpo.service;

import java.io.IOException;
import java.nio.file.Files;
import java.nio.file.Path;

import org.springframework.core.io.FileSystemResource;
import org.springframework.core.io.Resource;
import org.springframework.web.multipart.MultipartFile;

import com.cdutetc.nanpo.common.BusinessException;
import com.cdutetc.nanpo.common.ErrorCodeEnum;
import com.cdutetc.nanpo.config.StorageProperties;

/**
 * 本地磁盘存储实现（第13课）。
 * 第19课调整：去掉 @Service——实例改由 config/StorageConfig 工厂方法
 * 按 nanpo.storage.type 选择装配（另一个候选：MinioStorageService）；
 * 校验+改名逻辑上移到接口的 default 方法；新增 load() 供端点代理读取。
 * 两个历史坑仍防着：
 * 1. transferTo(相对路径) 会存到 multipart 临时目录——rootDir 一律转绝对路径；
 * 2. 目录可能不存在——启动时 createDirectories。
 */
public class LocalStorageService implements StorageService {

    private final Path rootDir;

    public LocalStorageService(StorageProperties props) {
        // 转绝对路径并规范化，防 transferTo 相对路径坑
        this.rootDir = Path.of(props.getDir()).toAbsolutePath().normalize();
        try {
            Files.createDirectories(rootDir);
        } catch (IOException e) {
            throw new IllegalStateException("无法创建上传目录：" + rootDir, e);
        }
    }

    @Override
    public String store(MultipartFile file) {
        String filename = validateAndRename(file);   // 接口 default 方法：校验+UUID 改名
        try {
            file.transferTo(rootDir.resolve(filename));
        } catch (IOException e) {
            throw new IllegalStateException("保存文件失败：" + filename, e);
        }
        return "/files/" + filename;
    }

    @Override
    public Resource load(String filename) {
        // 防路径穿越：解析后的路径必须还在上传目录内（第14课的老规矩搬进实现层）
        Path path = rootDir.resolve(filename).normalize();
        if (!path.startsWith(rootDir) || !Files.exists(path)) {
            throw new BusinessException(ErrorCodeEnum.FILE_NOT_FOUND);
        }
        return new FileSystemResource(path);
    }
}
```

**⑤ 新建 `service/MinioStorageService.java`**：

```java
package com.cdutetc.nanpo.service;

import org.springframework.core.io.InputStreamResource;
import org.springframework.core.io.Resource;
import org.springframework.web.multipart.MultipartFile;

import com.cdutetc.nanpo.common.BusinessException;
import com.cdutetc.nanpo.common.ErrorCodeEnum;
import com.cdutetc.nanpo.config.StorageProperties;

import io.minio.BucketExistsArgs;
import io.minio.GetObjectArgs;
import io.minio.MakeBucketArgs;
import io.minio.MinioClient;
import io.minio.PutObjectArgs;

/**
 * MinIO 对象存储实现（第19课）——第13课埋的暗线在此兑现：
 * KitchenController 注入的还是 StorageService 接口，业务代码一行未改；
 * 激活方式：nanpo.storage.type=minio（开发环境默认 local，互不干扰）。
 * 设计要点：store() 仍返回 /files/xxx.png 短路径，图片访问走应用端点代理——
 * 浏览器不感知 MinIO 的内网地址（预签名 URL 会暴露容器拓扑，且长达数百字符），
 * 将来加鉴权/换 CDN 也只动这一个类。
 */
public class MinioStorageService implements StorageService {

    private final MinioClient client;
    private final String bucket;

    public MinioStorageService(StorageProperties props) {
        StorageProperties.Minio minio = props.getMinio();
        this.client = MinioClient.builder()
                .endpoint(minio.getEndpoint())
                .credentials(minio.getAccessKey(), minio.getSecretKey())
                .build();
        this.bucket = minio.getBucket();
        try {
            // 桶不存在就建——幂等思想，和第8课菜单初始化同一招
            boolean exists = client.bucketExists(BucketExistsArgs.builder().bucket(bucket).build());
            if (!exists) {
                client.makeBucket(MakeBucketArgs.builder().bucket(bucket).build());
            }
        } catch (Exception e) {
            throw new IllegalStateException("MinIO 初始化失败（检查端点与密钥）：" + e.getMessage(), e);
        }
    }

    @Override
    public String store(MultipartFile file) {
        String filename = validateAndRename(file);   // 与本地实现共用接口 default 方法
        try {
            client.putObject(PutObjectArgs.builder()
                    .bucket(bucket)
                    .object(filename)
                    .stream(file.getInputStream(), file.getSize(), -1L)
                    .contentType(file.getContentType())
                    .build());
            return "/files/" + filename;   // 短路径——真实地址由端点代理屏蔽
        } catch (Exception e) {
            throw new IllegalStateException("上传 MinIO 失败：" + filename, e);
        }
    }

    @Override
    public Resource load(String filename) {
        try {
            return new InputStreamResource(
                    client.getObject(GetObjectArgs.builder().bucket(bucket).object(filename).build()));
        } catch (Exception e) {
            throw new BusinessException(ErrorCodeEnum.FILE_NOT_FOUND);
        }
    }
}
```

**⑥ 新建 `config/StorageConfig.java`**——装配车间：

```java
package com.cdutetc.nanpo.config;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import com.cdutetc.nanpo.service.LocalStorageService;
import com.cdutetc.nanpo.service.MinioStorageService;
import com.cdutetc.nanpo.service.StorageService;

/**
 * 存储实现的装配车间（第19课）。
 * 按 nanpo.storage.type 选择把哪个实现注册为 Bean——
 * 本地开发 local（默认），docker-compose 里 NANPO_STORAGE_TYPE=minio 一行切换。
 * 这就是第4课"@Autowired 按类型要人"的完整闭环：接口不变、实现可换、装配集中一处。
 */
@Configuration
public class StorageConfig {

    @Bean
    public StorageService storageService(StorageProperties props) {
        if ("minio".equals(props.getType())) {
            return new MinioStorageService(props);
        }
        return new LocalStorageService(props);
    }
}
```

两个实现都**没有** @Service 了——谁上岗由车间按配置决定。（另一种 Spring Boot 惯用做法是 `@ConditionalOnProperty` 条件注解，效果相同；工厂 @Bean 的好处是选择逻辑看得见。）

**② `controller/KitchenController.java` 整体替换**——新增 `/files/{filename}` 端点，download 改走抽象，本类不再直接碰磁盘：

```java
package com.cdutetc.nanpo.controller;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.core.io.Resource;
import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
import org.springframework.web.multipart.MultipartFile;

import com.cdutetc.nanpo.common.BusinessException;
import com.cdutetc.nanpo.common.ErrorCodeEnum;
import com.cdutetc.nanpo.common.Result;
import com.cdutetc.nanpo.dao.MenuRepository;
import com.cdutetc.nanpo.entity.Menu;
import com.cdutetc.nanpo.service.StorageService;

/**
 * 后厨管理（第13课新增）：菜品照片上架——经理/后厨用的接口，
 * 与服务顾客的 WaiterController 并存，一个店多个"窗口"。
 * 第14课新增：照片下载接口（Content-Disposition 让浏览器"另存为"）。
 * 第19课升级：本类不再直接碰磁盘（原来 download 里还有 Path/Files）——
 * 上传、下载、访问全部走 StorageService 抽象，本地/MinIO 由配置决定。
 */
@RestController
public class KitchenController {

    @Autowired
    private MenuRepository menuRepository;

    // 面向接口编程：注入的是 StorageService 而不是某个实现——
    // 第19课换 MinIO 后，这个类一行都没改
    @Autowired
    private StorageService storageService;

    // 上架菜品照片：multipart/form-data，文件字段名 file
    @PostMapping("/menu/{id}/image")
    public Result<String> uploadImage(@PathVariable Long id,
                                      @RequestParam("file") MultipartFile file) {
        Menu menu = menuRepository.findById(id)
                .orElseThrow(() -> new BusinessException(ErrorCodeEnum.DISH_NOT_FOUND));

        String url = storageService.store(file);   // 存文件，拿回访问路径
        menu.setImageUrl(url);                     // 记到菜单上
        menuRepository.save(menu);
        return Result.success(url);
    }

    // 图片访问端点（第19课）：统一由应用代理——本地实现读磁盘、MinIO 实现拉对象流，
    // 浏览器不感知存储拓扑。接替第14课 WebMvcConfig 的静态映射（它只认本地目录，
    // 存储搬进容器后不再够用）；前端 <img src="/files/xxx.png"> 的用法完全不变
    @GetMapping("/files/{filename}")
    public ResponseEntity<Resource> serveFile(@PathVariable String filename) {
        Resource resource = storageService.load(filename);
        String contentType = java.net.URLConnection.guessContentTypeFromName(filename);
        return ResponseEntity.ok()
                .contentType(MediaType.parseMediaType(
                        contentType != null ? contentType : "application/octet-stream"))
                .body(resource);
    }

    // 下载文件：和 /files/{filename} 直接访问的区别——
    // Content-Disposition: attachment 让浏览器弹出"另存为"而不是直接打开
    @GetMapping("/download/{filename}")
    public ResponseEntity<Resource> download(@PathVariable String filename) {
        Resource resource = storageService.load(filename);   // 读取也走抽象（第19课）
        return ResponseEntity.ok()
                .header(HttpHeaders.CONTENT_DISPOSITION, "attachment; filename=\"" + filename + "\"")
                .contentType(MediaType.APPLICATION_OCTET_STREAM)
                .body(resource);
    }
}
```

```dockerfile
# 阶段一：构建——用带 Maven 的 JDK 镜像编译打包
FROM maven:3.9-eclipse-temurin-17 AS builder
WORKDIR /app
# 先只拷 pom 下载依赖：这一层只要 pom 不变就命中缓存，改代码重建时快得多
COPY pom.xml .
RUN mvn -q dependency:go-offline
COPY src ./src
RUN mvn -q package -DskipTests

# 阶段二：运行——只要 JRE，镜像更小、攻击面更小
FROM eclipse-temurin:17-jre
# curl 供 docker-compose 的 healthcheck 探活 /actuator/health 用
RUN apt-get update && apt-get install -y --no-install-recommends curl \
    && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY --from=builder /app/target/*.jar app.jar
# 日志/LocalDateTime 时区更友好
ENV TZ=Asia/Shanghai
EXPOSE 8080
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```yaml
      # ===== 暗线二：存储换 MinIO =====
      NANPO_STORAGE_TYPE: minio
      NANPO_STORAGE_MINIO_ENDPOINT: http://minio:9000
      NANPO_STORAGE_MINIO_ACCESSKEY: nanpo
      NANPO_STORAGE_MINIO_SECRETKEY: nanpo123
      NANPO_STORAGE_MINIO_BUCKET: nanpo
      # ===== 密钥透传（宿主机没设就用默认值，不影响启动）=====
      NANPO_AI_KEY: ${NANPO_AI_KEY:-demo-key-not-set}
      NANPO_JWT_SECRET: ${NANPO_JWT_SECRET:-nanpo-dev-secret-change-me-please-0123456789}
    ports:
      - "8080:8080"
    healthcheck:
      test: ["CMD", "curl", "-sf", "http://localhost:8080/actuator/health"]
      interval: 10s
      timeout: 5s
      retries: 10

volumes:
  mysql-data:
  minio-data:
```

读懂五个关键设计：

- **host 名即服务名**：app 容器里连 `jdbc:mysql://mysql:3306/...`——`mysql` 这个主机名就是 compose 网络里的 MySQL 容器（自动 DNS）。容器之间用服务名互相找。
- **healthcheck + depends_on.condition**：MySQL 刚起那几秒是"活着但还没就绪"，直接连必挂——`mysqladmin ping` 通过了才允许 app 启动。**启动顺序是分布式系统的第一课**。
- **数据卷**：`mysql-data` 把数据落在 Docker 管理的卷里——`docker compose down` 删容器，数据还在；下次 `up` 接着用（想彻底清零：`down -v`）。
- **密钥透传**：`${NANPO_AI_KEY:-demo-key-not-set}`——宿主机设了就透传给容器，没设用默认。**compose 文件可以提交，真密钥永远只在环境里**。
- **环境变量覆盖 yml**：`SPRING_DATASOURCE_URL` 自动覆盖 `spring.datasource.url`（Boot 的规范行为，下划线对应点号）——**换数据库没改一行配置文件**。

## Step 6：开店！（15 分钟）

```bash
docker compose up --build -d
```

首次要拉基础镜像 + 容器内编译，10 分钟级等待属正常。看状态：

```bash
docker compose ps
```

三个容器 `Up`、mysql 和 app 标注 `(healthy)` 就绪后，按下一文件验收。

> **常见报错**
>
> | 现象 | 原因 | 解法 |
> |---|---|---|
> | app 反复重启 | MySQL 没就绪就连接失败（healthcheck 没配好） | 确认 depends_on 的 condition |
> | 上传报 Data too long for column 'image_url' | 存量库列还是 255（update 不改列宽） | `ALTER TABLE t_menu MODIFY image_url VARCHAR(1024);` |
> | `docker compose` 命令不存在 | 老 Docker 版本 | 升级或用 `docker-compose`（带横线） |
