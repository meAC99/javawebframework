# 第2课 · 课程导入：服务员接第一单

## 上一课发生了什么

你的店挂牌了：`http://localhost:8080/hello` 能看到开业标语。但顾客站在门口满脸问号——**怎么看菜单？怎么点菜？**

今天你招到第一位员工：**服务员（WaiterController）**。这一课里他一个人干所有活：背菜谱、接单、验菜、算账，甚至亲自下厨。他累不累？累。但店总算能营业了——而他"忙不过来"这件事，正是下一课的起点。

课结束时你的店将具备：

```
顾客浏览器（一个能点的网页）
   │  GET /menu        ← 查菜单
   │  POST /order      ← 提交点单 JSON
   ▼
服务员 WaiterController（验菜、算价、回小票）
```

你还会第一次体验完整的**前后端配合**：网页（前端）发请求 → Java 程序（后端）回数据 → 网页把数据画出来。

## 本课你将学会

1. HTTP 最常用的两招：GET（要数据）、POST（交数据），以及状态码 200/404/500 的含义
2. `@GetMapping` / `@PostMapping` / `@RequestBody`——方法参数怎么和 HTTP 请求对上
3. 前后端怎么"说同一种语言"：JSON 与 Java 对象自动互转
4. 用 lombok `@Data` 一键生成 getter/setter
5. 用浏览器 fetch 调用自己写的接口

## 先想一个问题：点单的数据长什么样？

顾客点单是"回锅肉 2 份、米饭 2 份"这样的清单。前后端约定用 JSON 传输：

```json
{
  "dishList": [
    { "dishName": "回锅肉", "count": 2 },
    { "dishName": "米饭", "count": 2 }
  ]
}
```

后端要做的：把这段 JSON **自动变成 Java 对象**（不用手动解析字符串），处理完再把结果**自动变回 JSON** 发回去。这个"自动"由第 1 课引入的 Jackson 完成，你只需要用对注解。
