# 第2课 · 动手做：从"能访问"到"能点菜"

共 4 步。**注意**：本课会故意留下三处"不规范"代码，它们是后面课程的伏笔，手册里会明说，照抄即可，别提前优化。

## Step 1：三个"数据口袋"——pojo 包（15 分钟）

前后端来回传的数据（点单请求、订单明细、小票）都需要 Java 类来装。创建包 `com.cdutetc.nanpo.pojo`，写三个类。

`pojo/OrderRequest.java`——顾客的点单请求：

```java
package com.cdutetc.nanpo.pojo;

import java.util.List;

import lombok.Data;

/**
 * 点单请求：前端提交的 JSON 会被自动装配成这个对象。
 * 对应 JSON 形如：{"dishList":[{"dishName":"回锅肉","count":2}]}
 */
@Data
public class OrderRequest {

    private List<DishCount> dishList;

    @Data
    public static class DishCount {
        private String dishName;
        private Integer count;
    }
}
```

`pojo/OrderItem.java`——小票上的一行（一道菜）：

```java
package com.cdutetc.nanpo.pojo;

import lombok.Data;

/**
 * 订单明细：一道菜买了几份、单价多少、小计多少。
 */
@Data
public class OrderItem {

    private String dishName;
    private Integer count;
    private Integer unitPrice;
    private Integer subTotal;
}
```

`pojo/OrderResponse.java`——回给顾客的小票：

```java
package com.cdutetc.nanpo.pojo;

import java.util.List;

import lombok.Data;

/**
 * 点单响应：返回给前端的"小票"。
 */
@Data
public class OrderResponse {

    private List<OrderItem> itemList;
    private Integer totalMoney;
    private String msg;
}
```

**关于 `@Data`**：lombok 在编译时自动生成所有 getter/setter、toString 等。没有它，这三个类每个要多写十几行模板代码。字段名和 JSON 的 key **一一对应**（`dishList` ↔ `"dishList"`），Jackson 靠这个名字对应完成自动装配。

> **坑**：装了 lombok 但 IDEA 没开注解处理（Annotation Processing），会报 `找不到符号 getXxx()`。设置位置：Settings → Build → Compiler → Annotation Processors → Enable。

## Step 2：服务员上岗——WaiterController（25 分钟）

创建 `controller/WaiterController.java`。**先看代码下方的三处"故意不规范"说明再动手**：

```java
package com.cdutetc.nanpo.controller;

import java.util.ArrayList;
import java.util.HashMap;
import java.util.List;
import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RestController;

import com.cdutetc.nanpo.pojo.OrderItem;
import com.cdutetc.nanpo.pojo.OrderRequest;
import com.cdutetc.nanpo.pojo.OrderResponse;

/**
 * 服务员。
 * 第2课的店里只有服务员一个人：他既背菜谱、又验菜算账、还要顺手"炒菜"——
 * 所有活都挤在这一个类里，正是第3课"招人分工（三层架构）"要解决的问题。
 */
@RestController
public class WaiterController {

    // 菜谱暂且写死在代码里（第8课将搬进数据库）
    private static final Map<String, Integer> MENU = new HashMap<>();
    static {
        MENU.put("回锅肉", 18);
        MENU.put("鱼香肉丝", 16);
        MENU.put("麻婆豆腐", 12);
        MENU.put("番茄炒蛋", 10);
        MENU.put("蛋炒饭", 8);
        MENU.put("米饭", 1);
    }

    // 查菜单：故意返回裸 Map，格式不规范——第5课"统一返回"时回来整改
    @GetMapping("/menu")
    public Map<String, Integer> getMenu() {
        return MENU;
    }

    // 点单：@RequestBody 把前端提交的 JSON 自动装配成 OrderRequest 对象
    @PostMapping("/order")
    public OrderResponse order(@RequestBody OrderRequest orderRequest) {
        OrderResponse resp = new OrderResponse();
        List<OrderItem> itemList = new ArrayList<>();
        int total = 0;

        for (OrderRequest.DishCount dc : orderRequest.getDishList()) {
            String dishName = dc.getDishName();
            Integer count = dc.getCount();

            // 菜单里没有这道菜：直接抛出运行时异常。
            // 浏览器会看到丑陋的 500 错误页——第6课"统一异常处理"回来整改
            if (!MENU.containsKey(dishName)) {
                throw new RuntimeException("菜品不存在：" + dishName);
            }
            int unitPrice = MENU.get(dishName);
            int subTotal = unitPrice * count;
            total += subTotal;

            OrderItem item = new OrderItem();
            item.setDishName(dishName);
            item.setCount(count);
            item.setUnitPrice(unitPrice);
            item.setSubTotal(subTotal);
            itemList.add(item);

            // 服务员顺手把菜也"炒"了（第3课把这份活交给厨师和墩子）
            System.out.printf("[服务员] 炒好了 %s x %d%n", dishName, count);
        }

        resp.setItemList(itemList);
        resp.setTotalMoney(total);
        resp.setMsg("下单成功，请到取餐口稍等～");
        return resp;
    }
}
```

看懂三个新注解：

- `@GetMapping("/menu")`：GET 请求 `/menu` → 返回 Map，Jackson 自动转成 JSON 对象。
- `@PostMapping("/order")`：POST 请求 `/order` 才能进这个方法（点单是"提交数据"，用 POST 是 REST 惯例）。
- `@RequestBody OrderRequest`：把请求体里的 JSON **自动装配**成 OrderRequest 对象——字段名对上就填，对不上就留 null。没有它，Spring 会以为参数来自 URL。

**本课故意留的三处不规范（伏笔，后面课逐一兑现）**：

| 位置 | 不规范之处 | 谁来修 |
|---|---|---|
| 菜谱 `MENU` | 写死在代码里，改价要改代码重新发版 | 第 8 课搬进数据库 |
| `getMenu()` | 返回裸 Map，没有统一格式 | 第 5 课统一返回 Result |
| 点错菜 | 直接抛 `RuntimeException`，顾客看到丑陋 500 页 | 第 6 课统一异常处理 |

## Step 3：给顾客一个能点的网页（20 分钟）

创建 `src/main/resources/static/index.html`（放在 static 目录下，Spring Boot 自动对外服务——第 1 课"约定优于配置"的又一个例子：不用写任何路由，`http://localhost:8080/` 自动打开它）：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
    <meta charset="UTF-8">
    <title>南坡小炒·点餐</title>
    <style>
        body { font-family: "PingFang SC", sans-serif; max-width: 420px; margin: 40px auto; background: #faf7f2; padding: 0 16px; }
        h1 { text-align: center; }
        .dish { display: flex; justify-content: space-between; align-items: center; padding: 10px 12px; border-bottom: 1px dashed #ddd; }
        .price { color: #c0392b; font-weight: bold; }
        button { width: 100%; padding: 12px; margin-top: 16px; font-size: 16px; background: #c0392b; color: #fff; border: none; border-radius: 6px; cursor: pointer; }
        input[type=number] { width: 56px; }
        pre { background: #333; color: #9f9; padding: 12px; border-radius: 6px; min-height: 48px; font-size: 12px; }
    </style>
</head>
<body>
<h1>🍜 南坡小炒</h1>

<!-- 菜单区：页面打开后由 fetch(/menu) 填充 -->
<div id="menu">菜单加载中…</div>

<button onclick="order()">下单</button>

<!-- 小票区：展示 POST /order 的返回结果 -->
<pre id="result">小票将显示在这里</pre>

<script>
    // 页面打开：向 GET /menu 要菜单，渲染成"菜名+价格+数量输入框"列表
    fetch('/menu')
        .then(resp => resp.json())
        .then(menu => {
            let html = '';
            for (const [dishName, price] of Object.entries(menu)) {
                html += `
                <div class="dish">
                    <span>${dishName} <span class="price">￥${price}</span></span>
                    <span>数量 <input type="number" min="0" value="0" data-dish="${dishName}"></span>
                </div>`;
            }
            document.getElementById('menu').innerHTML = html;
        });

    // 点击下单：收集数量大于0的菜，POST /order 提交 JSON
    function order() {
        const dishList = [];
        document.querySelectorAll('input[data-dish]').forEach(input => {
            if (input.value > 0) {
                dishList.push({ dishName: input.dataset.dish, count: Number(input.value) });
            }
        });
        if (dishList.length === 0) {
            alert('还没点菜呢');
            return;
        }
        fetch('/order', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ dishList: dishList })
        })
        .then(resp => resp.json())
        .then(receipt => {
            document.getElementById('result').innerText = JSON.stringify(receipt, null, 2);
        });
    }
</script>
</body>
</html>
```

看懂前端两段核心 JS：

- `fetch('/menu')`：浏览器向**同源**的后端发 GET 请求，拿到 JSON 后循环画菜单。（因为是同一个 8080 端口服务，所以没有跨域问题）
- `fetch('/order', { method: 'POST', body: JSON.stringify(...) })`：把用户勾的菜拼成 `{"dishList":[...]}` 提交——**和你 Step 1 定义的 JSON 结构完全一致**，这就是"前后端契约"。
