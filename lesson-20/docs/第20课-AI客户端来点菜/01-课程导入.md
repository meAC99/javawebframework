## 巡礼一眼：Spring AI 之后的新方向

课堂十分钟口头巡礼，知道名字和定位即可（都不入本课代码）：

- **Spring gRPC**（2025 年 1.0）：服务之间的高性能 RPC。REST 用 HTTP 文本，gRPC 用二进制协议流——微服务内部通信用它，快一个数量级。
- **Spring Modulith**：模块化单体。想在微服务之前先管好单体内部的边界（模块间依赖验证、模块化文档）——"先 Modulith 后微服务"是很多团队的现实路线。
- **Spring Boot 4 / Framework 7**（本课程全程在用）：starter 改名、自动配置模块化（第 7 课的 h2console 坑）、API 版本化、JSpecify 空安全、虚拟线程（`spring.threads.virtual.enabled=true` 一行开启）。

## 本课主角：MCP（Model Context Protocol）

第 18 课的**工具调用**是这个方向：

```
你的程序 --调用--> 大模型（模型需要数据时"回调"你注册的工具）
```

**MCP 把方向反过来**：

```
大模型客户端（Claude Desktop / Cursor 等） --调用--> 你的程序
```

你的系统对 AI 客户端**开放一组工具**（查菜单、下订单），AI 客户端连上后，用户对它说"帮我点份回锅肉"，它自己决定调用你的 `placeOrder` 工具。**你的南坡小炒，成了大模型世界里的一个"技能"。**

协议层面：MCP 是一个标准化协议（JSON-RPC 消息 + SSE 传输），Spring AI 提供了 server 端 starter——你只需要把第 18 课的 `@Tool` 方法注册出去。**又是旧代码复用**：`MenuTool` 原样登场，新写一个 `OrderTool`。

一个新问题值得先想：MCP 调用**不经过 HTTP 拦截器**（AI 客户端不走你的 REST 接口），也就**没有登录态**——那第 16 课"订单必须记名"的规矩怎么守？（答案在动手文件里，try-finally 藏着第 16 课的 ThreadLocal 老规矩。）
