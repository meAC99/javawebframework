# 第20课 · 验证、提交与结课

## 一、验证清单（亲手扮演一次"AI 客户端"）

**1. 启动日志**：`Enable tools capabilities` + `Registered tools: 2` 两行在。

**2. 用 curl 完成 MCP 握手（三条命令的魔术）**

MCP 走 SSE：先建会话流，再往消息端点发 JSON-RPC。开三个终端（或在 IDEA 里开三个 Terminal）：

**终端 A——建立 SSE 会话（挂着别关）：**

```bash
curl -N http://localhost:8080/sse
```

预期立刻输出一行：

```
event:endpoint
data:/mcp/message?sessionId=xxxxxxxx-xxxx-....
```

**抄下这个 sessionId**（响应都从终端 A 的流里回来）。

**终端 B——初始化 + 列工具：**

```bash
SID=抄下来的sessionId
MSG="http://localhost:8080/mcp/message?sessionId=$SID"

curl -s -X POST "$MSG" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"curl","version":"1.0"}}}'

curl -s -X POST "$MSG" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","method":"notifications/initialized"}'

curl -s -X POST "$MSG" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":2,"method":"tools/list"}'
```

回终端 A 看：初始化应答 + **tools 列表**里躺着 `getMenu` 和 `placeOrder`——这就是 AI 客户端连上你的店时看到的东西。

**终端 C（或还用 B）——AI 真的下单：**

```bash
curl -s -X POST "$MSG" -H "Content-Type: application/json" \
  -d '{"jsonrpc":"2.0","id":3,"method":"tools/call","params":{"name":"placeOrder","arguments":{"dishName":"回锅肉","count":1}}}'
```

终端 A 的流里很快出现：

```
下单成功：订单号 1，总额 18.00 元
```

**一家由 AI 客户端点单的饭店，就此诞生。** 顺手发 16.7（登录后）翻账本——这笔订单的 `username` 是 `ai-guest`（系统身份）。

**3. 真·AI 客户端体验（有条件选做）**

如果你有支持 MCP 的客户端（Claude Desktop、Cursor 等），在它的 MCP 配置里加一个指向 `http://localhost:8080/sse` 的 server（各客户端配置格式略有差异，查其文档的 "MCP / SSE server" 一节），然后对它说：

> "查一下南坡小炒的菜单，帮我点一份不辣的菜。"

看它自主决定：先调 `getMenu` 查菜单 → 挑一道不辣的 → 调 `placeOrder` 下单。**你写的是第 9 课的收银台，AI 客户端隔着 MCP 协议在用它。**

**4. 回归**：2.1 / 2.2 / 17.1——REST 世界一切如常（MCP 是"加开的窗口"，不动旧窗口）。
