# 第20课 · 动手做：MCP Server 上线

共 5 步，代码量是二十课里最小的一课——前面十九课的复利。

## Step 1：pom 加 MCP server starter（3 分钟）

```xml
		<!-- 第20课：MCP Server——把本店工具开放给 AI 客户端（Claude Desktop 等）点菜 -->
		<dependency>
			<groupId>org.springframework.ai</groupId>
			<artifactId>spring-ai-starter-mcp-server-webmvc</artifactId>
		</dependency>
```

（版本仍由 spring-ai-bom 统一管理。）这个 starter 做三件事：在你的 web 应用上开 MCP 端点（SSE 传输）、扫描/注册工具、说 JSON-RPC 协议。

## Step 2：OrderTool——MCP 下单工具（15 分钟）

新建 `service/OrderTool.java`：

```java
package com.cdutetc.nanpo.service;

import java.util.List;

import org.springframework.ai.tool.annotation.Tool;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;

import com.cdutetc.nanpo.common.UserContext;
import com.cdutetc.nanpo.dto.OrderRequest;
import com.cdutetc.nanpo.vo.OrderVO;

/**
 * MCP 下单工具（第20课）：AI 客户端通过 MCP 直接给本店下订单。
 * 注意一个细节：MCP 调用不经过 HTTP 拦截器，没有登录态——
 * 工具里以"AI 来客"系统身份登记下单人，用完立刻清理
 * （第16课 ThreadLocal 的规矩：不清理会串号）。
 */
@Component
public class OrderTool {

    @Autowired
    private OrderService orderService;   // 又是老收银台——MCP 也只是新入口

    @Tool(description = "为顾客下一笔订单：传入菜名和份数，返回订单号与金额")
    public String placeOrder(String dishName, int count) {
        OrderRequest request = new OrderRequest();
        OrderRequest.DishCount dc = new OrderRequest.DishCount();
        dc.setDishName(dishName);
        dc.setCount(count);
        request.setDishList(List.of(dc));
        try {
            UserContext.set(new UserContext.CurrentUser(0L, "ai-guest"));
            OrderVO vo = orderService.createOrder(request);
            return "下单成功：订单号 " + vo.getOrderId() + "，总额 " + vo.getTotalMoney() + " 元";
        } finally {
            UserContext.clear();
        }
    }
}
```

看懂"没有登录态怎么办"的答案：

- `UserContext.set(new CurrentUser(0L, "ai-guest"))`——给这次调用一个**系统身份**（AI 来客），订单照常记名（`username=ai-guest`），第 16 课的规矩不破。
- **`try-finally` 里 clear()**——第 16 课用血泪换的规矩在 MCP 场景再次生效：MCP 请求同样跑在线程池上，不清理就会串号。
- 工具**返回 String** 而不是 VO——工具的返回值是**给模型看的**，模型再组织成人话告诉用户。返回订单号和金额的文本刚刚好。

## Step 3：McpConfig——把工具挂出去（10 分钟）

新建 `config/McpConfig.java`：

```java
package com.cdutetc.nanpo.config;

import org.springframework.ai.tool.ToolCallbackProvider;
import org.springframework.ai.tool.method.MethodToolCallbackProvider;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

import com.cdutetc.nanpo.service.MenuTool;
import com.cdutetc.nanpo.service.OrderTool;

/**
 * MCP（Model Context Protocol）服务配置（第20课彩蛋）。
 * 把本店的工具注册到 MCP Server——任何支持 MCP 的 AI 客户端
 * （Claude Desktop / Cursor / 各类 MCP 客户端）都能连进来：
 * 查菜单（MenuTool，第18课旧代码原样复用）、下订单（OrderTool，本课示范）。
 * 这就是"AI 客户端真的进来点菜"：你的系统成了大模型的工具。
 */
@Configuration
public class McpConfig {

    @Bean
    public ToolCallbackProvider nanpoTools(MenuTool menuTool, OrderTool orderTool) {
        return MethodToolCallbackProvider.builder()
                .toolObjects(menuTool, orderTool)
                .build();
    }
}
```

`MethodToolCallbackProvider` 把 `@Tool` 方法包装成 MCP 协议的回调。注意 **MenuTool 是第 18 课的旧类，一字未改**——同一个工具箱，既给自己的小智用，也开放给外部 AI 客户端。

## Step 4：yml 起个名（2 分钟）

`spring.ai` 段里（openai 之后）加：

```yaml
    # 第20课：MCP Server——本店工具对外（AI 客户端）开放的窗口
    mcp:
      server:
        name: nanpo-xiaochao
        version: 1.0.0
```

## Step 5：重启，看"Registered tools"（5 分钟）

```bash
./mvnw spring-boot:run
```

启动日志里找这两行（本课的"开门营业"宣言）：

```
McpServerAutoConfiguration : Enable tools capabilities, notification: true
McpServerAutoConfiguration : Registered tools: 2
```

`Registered tools: 2` = getMenu + placeOrder。MCP 端点用 **SSE 传输**挂在应用上：`GET /sse` 建会话、`POST /mcp/message?sessionId=...` 收发 JSON-RPC。验证见下一文件——包括用 curl 亲手扮演一次"AI 客户端"。

> **常见报错**
>
> | 现象 | 原因 | 解法 |
