# 第17课 · 课程导入：AI 服务员上岗

## 上一课发生了什么

店员齐了、账目清了、会员有了——南坡小炒已经是家像模像样的店。老板叼着牙签来了："现在 AI 这么火，**能不能让 AI 当服务员？顾客发一句'来份不辣的下饭菜'，它直接把菜点了。**"

从这节课起进入最后阶段：给店里雇一位 **AI 服务员"小智"**。本课先让它学会**聊天**（回答顾客问题），下一课再让它学会**真的下单**。

## 先想清楚：大模型接口，本质上是个 HTTP 接口

不管宣传多玄乎，你调用大模型的方式和第 2 课调用自己写的接口**没有本质区别**：

```
POST https://open.bigmodel.cn/api/paas/v4/chat/completions
Authorization: Bearer <你的APIKey>

{ "model": "glm-4-flash", "messages": [{"role":"user","content":"你们有什么菜？"}] }

→ 响应 JSON 里带着 AI 生成的话
```

带鉴权的 HTTP POST、JSON 进 JSON 出——第 2 课的功底直接复用。而 **Spring AI** 帮你把这个 HTTP 细节包掉：你面对的是 `ChatClient` 对象，配置好端点和 Key，一行代码发起对话。

三个准备认识：

1. **OpenAI 兼容端点**：智谱 GLM、DeepSeek、DashScope 都提供"OpenAI 格式"的接口——所以 Spring AI 的 openai 客户端可以连它们任何一家，**换模型只改配置**（又是配置外部化，第 15 课的 Key、第 19 课的数据库连接，同一个思想贯穿到底）。
2. **系统提示词（System Prompt）**：给 AI 定"人设"的一段话——"你是南坡小炒的服务员小智……"。人设决定了它说话的口吻和边界。
3. **Key 是敏感信息**：和第 15 课的 JWT 密钥一样，用环境变量 `NANPO_AI_KEY` 注入，**永远不进代码和仓库**。

## 本课你将学会

1. Spring AI 接入：BOM 管版本、starter 引入、`spring.ai.openai` 三段配置
2. `ChatClient` + 系统提示词（人设）
3. API Key 的环境变量管理；无 Key 时的优雅降级
