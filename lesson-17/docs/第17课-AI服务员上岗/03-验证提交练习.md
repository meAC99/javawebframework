```
POST http://localhost:8080/ai/chat

{ "message": "你们店有什么菜？有什么不辣的吗？" }
```

## 二、验证清单

**1. 无 Key 状态（降级路径，必测）**

直接发送 17.1（此时你没配环境变量）：

```json
{"code":50002,"data":null,"msg":"AI 服务暂时不可用，请稍后再试"}
```

**为什么这是正确行为而不是失败**：小智请假，店照开——菜单、下单、登录一切正常（顺手回归 2.1/2.2）。生产系统管这叫**优雅降级**：增强型功能挂了，不能拖垮核心功能。体会一下：如果 Step 3 没有 catch，这里会喷出 50001 和一屏英文堆栈，前端还要写特殊逻辑区分"店炸了"和"AI 没配"。

**2. 有 Key 状态（完整体验）**

停掉程序，带 Key 重启：

```bash
export NANPO_AI_KEY=你的智谱Key
./mvnw spring-boot:run
```

再发 17.1——预期 `data` 里是热情的两三句话（"本店招牌是回锅肉，不辣的话推荐番茄炒蛋和蛋炒饭……"之类，每次措辞不同，正常——temperature 在起作用）。浏览器点餐页的"问小智"同样可用。

**3. 回归**：2.1 菜单 / 15.3 登录 / 2.2 下单 / 7.1 h2-console——全部正常（AI 是"外挂"，不碰主链路）。

## 四、课后练习

1. **换脑子**：环境变量 `NANPO_AI_BASE=https://api.deepseek.com`、`NANPO_AI_MODEL=deepseek-chat`（配 DeepSeek 的 Key），重启——**一行代码没改**，小智换了大脑。再把人设里的"小智"改成"小deep"，观察语气变化。
2. **温度实验**：yml 里把 temperature 改成 0.1 和 1.5，各问三次同一个问题——对比回复的"稳定性"与"放飞程度"。
3. **思考题**：小智现在是"单轮对话"——你问一句它答一句，不记得上一句。要让"我先问有什么菜，再说那就来第一份"能成功，需要把什么发给模型？（提示：`messages` 数组可以带历史；Spring AI 有 ChatMemory 组件——课后查查怎么接。）

## 五、下一课预告

小智能说会道，但它说的话**变不成订单**——顾客说"来份不辣的下饭菜"，小智只能回"好的呢"，然后呢？收银台毫不知情。

下一课解决"AI 与业务系统对接"的两个正经姿势：**结构化输出**（让模型直接吐出符合第 2 课契约的 `OrderRequest` JSON，程序再反序列化成对象）和**工具调用**（让模型在需要时"打电话"回来查你的真实菜单）。你将亲眼看到：**AI 下单复用的还是第 9 课那个 OrderService——业务代码一行不改**，十八课攒下的分层在此刻兑现最大红利。
