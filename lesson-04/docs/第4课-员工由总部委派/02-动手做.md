# 第4课 · 动手做：把人事权交给容器

共 3 步。这次的 diff 会非常小——**删两行 new，加几个注解**——但每一行都值得看懂。

## Step 1：两个服务登记进容器（15 分钟）

**① SideDishService 加注解 + "报到"日志**，改成：

```java
package com.cdutetc.nanpo.service;

import org.springframework.stereotype.Service;

/**
 * 墩子（配菜员）：只负责配菜这一件事——单一职责。
 * 第3课：普通 Java 类，由服务员手动 new。
 * 第4课：加上 @Service，人事权上交——由 IoC 容器创建和管理，
 *        启动时实例化单例，等着被容器"派"到需要的地方（依赖注入）。
 */
@Service
public class SideDishService {

    // 报到日志：证明 Bean 在容器启动时就被创建（而不是第一次请求时才创建），
    // 且全店只此一份（单例），多个使用者共享同一个对象
    public SideDishService() {
        System.out.println("[墩子] 向容器报到，单例就位：" + Integer.toHexString(System.identityHashCode(this)));
    }

    public void prepareSideMaterial(String dishName, int count) {
        System.out.printf("[墩子] %s x %d 配菜完成%n", dishName, count);
    }
}
```

**② CookService 同样处理**（同样的三处变化：import、类头注释、`@Service` + 构造器）：

```java
package com.cdutetc.nanpo.service;

import org.springframework.stereotype.Service;

/**
 * 厨师：只负责炒菜这一件事——单一职责。
 * 第3课：普通 Java 类，由服务员手动 new。
 * 第4课：加上 @Service，人事权上交——由 IoC 容器创建和管理。
 */
@Service
public class CookService {

    // 报到日志：证明 Bean 在容器启动时就被创建，且全店只此一份（单例）
    public CookService() {
        System.out.println("[厨师] 向容器报到，单例就位：" + Integer.toHexString(System.identityHashCode(this)));
    }

    public void cookDish(String dishName, int count) {
        System.out.printf("[厨师] %s x %d 炒菜完成%n", dishName, count);
    }
}
```

看懂 `@Service`：它本身只是 `@Component` 的"别名"（语义化注解），作用只有一个——**告诉容器：这个类归你管，启动时创建一个实例放进容器**。类似的还有 `@RestController`（接口层，你第 1 课就在用了）、`@Repository`（数据层，第 8 课见）。四者机制完全相同，名字是给人看的。

构造器里的"报到日志"是这节课的**证据装置**：它会在对象被创建时打印一串哈希码。待会你要用它回答两个问题——员工**什么时候**上岗？上岗了**几份**？

## Step 2：服务员不再自己招人（15 分钟）

修改 `WaiterController.java` 两处：

**① 删掉两行 new**：

```java
    // 删除第3课的这两行——服务员不再自己招人：
    // private final SideDishService sideDishService = new SideDishService();
    // private final CookService cookService = new CookService();
```

**② 换成声明式注入**（原位置写入）：

```java
    // 第4课：由第3课的"手动 new"改为容器注入——控制权反转(IoC)。
    // 对比：第3课 new SideDishService()，服务员自己造人、每个服务员各造一份；
    //      现在 @Autowired 声明依赖，容器启动时把全局唯一的单例赋值进来
    @Autowired
    private SideDishService sideDishService;
    @Autowired
    private CookService cookService;
```

补 import：

```java
import org.springframework.beans.factory.annotation.Autowired;
```

顺便把类头注释追加一行店史：

```java
 * 第4课：人事权上交——员工由总部(IoC 容器)统一委派，服务员不再自己 new，
 *        只声明"我需要谁"(@Autowired)，容器在启动时把员工送上门（依赖注入）。
```

**品味一下发生了什么**：`@Autowired` 的意思不是"创建一个"，而是"**我需要一个，容器你看着办**"。字段从此不再由你赋值——容器在启动时通过反射把单例塞进来。创建、装配、共享，全是容器的事。

> **坑**：如果启动报 `NoSuchBeanDefinitionException`，八成是服务类忘了加 `@Service`——容器里没这个人，你却要人。
