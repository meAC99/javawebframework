## 一、requests.http 追加

```
### 15.1 办卡（注册）
POST http://localhost:8080/register
Content-Type: application/json

{ "username": "xiaoming", "password": "123456", "nickname": "小明" }

### 15.2 重复办卡（预期 code=40407）
POST http://localhost:8080/register
Content-Type: application/json

{ "username": "xiaoming", "password": "123456" }

### 15.3 登录（预期拿到 token；把它粘到 jwt.io 解码看看）
POST http://localhost:8080/login
Content-Type: application/json

{ "username": "xiaoming", "password": "123456" }

### 15.4 密码错误（预期 code=40408）
POST http://localhost:8080/login
Content-Type: application/json

{ "username": "xiaoming", "password": "wrong" }
```

## 二、验证清单（全过才算下课）

**1. 发送 15.1** → `{"code":200,"data":null,"msg":"操作成功"}`

**2. 发送 15.2** → `{"code":40407,...,"msg":"用户名已被占用"}`

**3. 发送 15.3 登录** → 预期：

```json
{"code":200,"data":{"token":"eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiIxIiwidXNlcm5hbWUi...","expiresIn":120,"nickname":"小明"},"msg":"操作成功"}
```

**4. 解码实验（本课的"哇"时刻）**：复制 `data.token` 的完整值，打开 **https://jwt.io**，粘贴进去——右侧立刻显示解开的 Payload：

```json
{
  "sub": "1",
  "username": "xiaoming",
  "iat": 1788701062,
  "exp": 1788708262
}
```

自己核对两件事：`sub` 是数据库里的用户 id；`exp - iat = 7200` 秒 = 120 分钟，和 yml 的 `ttl-minutes` 分毫不差。**顺便在 jwt.io 里改一个字母再粘回来**——页面立刻飘红 "Invalid Signature"：这就是第三段签名的防篡改，眼见为实。

**5. 发送 15.4** → `{"code":40408,...,"msg":"用户名或密码错误"}`

**6. h2-console 取证：库里存的是哈希不是明文**

```sql
SELECT USERNAME, PASSWORD, NICKNAME FROM T_USER;
```

预期：PASSWORD 是 `$2a$10$...` 开头的 60 位乱码——**不是 123456**。再注册第二个用户（15.1 改成 xiaohong，密码同样用 123456），再查一次：**两个哈希完全不同**——同一个密码、不同的随机盐，这就是"彩虹表失效"的实证。

**7. 回归**：2.1 菜单、2.2 下单一切如常——**本课只加了"发卡"，还没"查票"**，所以现有接口还不需要令牌（下一课才管）。

## 四、课后练习

1. **亲手缩短有效期**：把 `ttl-minutes` 改成 `1`，重启重新登录，jwt.io 解码看 `exp-iat` 变成 60——顺便体会：现在每次改有效期都要重启，而它明明只是个配置。（改回 120。）
2. **暴力破解成本体感**：写个循环调 10 次 15.4（密码全错），观察响应时间——每次都要跑一遍 BCrypt 的 matches（几十毫秒的"慢"）。如果用的是普通 MD5，10 次可能 1 毫秒都不到——攻击者每秒能多试几万倍。
3. **思考题**：JWT 发出去之后，服务器**没有存**它（无状态）——那"退出登录/吊销这张卡"怎么做得到？（提示：做不到立即吊销，这正是 JWT 的代价；业界方案：短有效期+黑名单、或第 16 课的"长短双卡"设计——带着问题看下一课。）

## 五、下一课预告

会员卡能发了，但店里还没人查票：现在的 `/order` 谁都能调，会员卡形同虚设。下一课你将雇佣一位**查票员（拦截器 JwtInterceptor）**：所有下单请求先亮卡（请求头 `Authorization: Bearer xxx`），查完票把"当前会员"放进 `ThreadLocal`——订单从此**记名**。

你还会遇到一个真实系统的经典设计——**长短双令牌**：现在这张 120 分钟的卡，太短则天天重新登录、太长则丢了很危险。解法是发两张：15 分钟的"短卡"天天用 + 7 天的"长卡"只用来续卡。前端也将迎来第五次联动：登录框、令牌保管、自动带卡下单。
