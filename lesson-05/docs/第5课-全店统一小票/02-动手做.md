# 第5课 · 动手做：Result 信封 + 三接口改造 + 前端联动

共 4 步。**顺序有讲究**：先写信封，再改后端，然后你会看到前端"坏了"，最后修好前端。

## Step 1：common 包——错误码字典 + Result 信封（20 分钟）

创建包 `com.cdutetc.nanpo.common`。

`common/ErrorCodeEnum.java`——错误码字典：

```java
package com.cdutetc.nanpo.common;

import lombok.Getter;

/**
 * 全店错误码字典：一眼看出错在哪一层。
 * 200 成功；4xxxx 业务类（顾客的问题）；5xxxx 系统类（店家的问题）
 */
@Getter
public enum ErrorCodeEnum {

    SUCCESS(200, "操作成功"),

    /* 4xxxx 业务类错误 */
    DISH_NOT_FOUND(40401, "该菜品不存在"),

    /* 5xxxx 系统类错误 */
    SYSTEM_ERROR(50001, "服务器内部错误");

    private final Integer code;
    private final String msg;

    ErrorCodeEnum(Integer code, String msg) {
        this.code = code;
        this.msg = msg;
    }
}
```

错误码规则（以后每课都在往这张字典里加词）：**4 开头是顾客的问题**（点的菜不存在、密码错），**5 开头是店家的问题**（程序炸了）。看到码就知道该向谁道歉。

`common/Result.java`——统一信封：

```java
package com.cdutetc.nanpo.common;

import lombok.Data;

/**
 * 统一返回"小票"：第5课起，全店所有接口的返回都是这个格式。
 * {"code": 200, "msg": "操作成功", "data": {...}}
 *
 * @param <T> data 的类型——泛型让同一张小票能装任何数据（菜单、订单、字符串…）
 */
@Data
public class Result<T> {

    private Integer code;   // 200 成功；4xxxx 业务失败；5xxxx 系统错误
    private String msg;     // 给人看的信息
    private T data;         // 给程序用的数据

    // ---- 静态工厂：调用方一行搞定，不用每次 new + setXxx 三连 ----

    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(ErrorCodeEnum.SUCCESS.getCode());
        r.setMsg(ErrorCodeEnum.SUCCESS.getMsg());
        r.setData(data);
        return r;
    }

    public static <T> Result<T> success() {
        return success(null);
    }

    public static <T> Result<T> fail(Integer code, String msg) {
        Result<T> r = new Result<>();
        r.setCode(code);
        r.setMsg(msg);
        return r;
    }

    public static <T> Result<T> fail(ErrorCodeEnum errorCodeEnum) {
        return fail(errorCodeEnum.getCode(), errorCodeEnum.getMsg());
    }
}
```

看懂静态工厂：`Result.success(menu)` 一行顶四行（new、setCode、setMsg、setData），而且调用处读起来就是人话。这四个方法是本课程出镜率最高的代码之一。

## Step 3：先重启，看看"前端坏了"（5 分钟，故意的一步）

```bash
./mvnw spring-boot:run
```

先验证后端确实统一了——发送 `requests.http` 里的 **1.1 开业检查**，预期：

```json
{"code":200,"data":"南坡小炒，本店开业！","msg":"操作成功"}
```

然后打开浏览器 `http://localhost:8080/`——**菜单区永远停在"菜单加载中…"**。打开浏览器开发者工具（F12）→ Console，能看到 `TypeError: menu is not iterable` 之类的报错。

**为什么坏**：前端在等"裸 Map"（`{"回锅肉":18}`），后端现在给的是信封（`{"code":...,"data":{...}}`）。前端拿到信封后直接当菜单遍历，当然失败。这就是**契约变更**——一端改了格式，另一端必须同步。记住这种感觉，工作里它常在你不打招呼的时候出现。

## Step 4：修前端——拆信封取 data（10 分钟）

修改 `index.html` 的两处 JS：

**① 菜单加载——从 `result.data` 里取菜单**，把 fetch('/menu') 那段换成：

```js
    // 第5课适配：后端统一返回 Result{code,msg,data} 后，菜单要从 result.data 里取
    fetch('/menu')
        .then(resp => resp.json())
        .then(result => {
            const menu = result.data;
            let html = '';
            for (const [dishName, price] of Object.entries(menu)) {
                html += `
                <div class="dish">
                    <span>${dishName} <span class="price">￥${price}</span></span>
                    <span>数量 <input type="number" min="0" value="0" data-dish="${dishName}"></span>
                </div>`;
            }
            document.getElementById('menu').innerHTML = html;
        });
```

**② 下单结果——展示整个信封**，把 order() 里的 `.then(result => {...})` 换成：

```js
        .then(resp => resp.json())
        .then(result => {
            // 第5课：小票直接展示整个 Result 信封——code/msg/data 一目了然
            document.getElementById('result').innerText = JSON.stringify(result, null, 2);
        })
        .catch(() => {
            // 点了不存在的菜：后端还是直接抛异常(第2课遗留)，返回的是 500 HTML 错误页，
            // JSON 解析失败会走到这里——这个丑陋报错，第6课"统一异常处理"来修复
            document.getElementById('result').innerText = '❌ 服务器开小差了（500）';
        });
```

刷新页面，菜单回来了——信封拆对了。

> **坑**：浏览器改了 HTML 不生效？强刷（Cmd+Shift+R）清缓存。
