## Step 1：JwtUtil 升级为双卡（15 分钟）

**① yml**——把第 15 课的 `ttl-minutes: 120` 换成两行：

```yaml
  jwt:
    secret: ${NANPO_JWT_SECRET:nanpo-dev-secret-change-me-please-0123456789}
    access-ttl-minutes: 15     # 短卡：15 分钟（第15课是单张120分钟，第16课拆成长短双卡）
    refresh-ttl-days: 7        # 长卡：7 天，只用来续卡
```

**② `common/JwtUtil.java`** 整体升级（类头注释更新，方法重排）：

```java
package com.cdutetc.nanpo.common;

import java.nio.charset.StandardCharsets;
import java.time.Duration;
import java.time.Instant;
import java.util.Date;

import javax.crypto.SecretKey;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.Jwts;
import io.jsonwebtoken.security.Keys;

/**
 * JWT 工具。
 * 第15课：单张卡（120 分钟）。
 * 第16课升级为长短两张卡：
 *   accessToken（15分钟，天天用）+ refreshToken（7天，只用来续卡）——
 *   短卡丢了损失小，长卡尽量少出门，被偷的风险就小；
 *   两张卡靠 Payload 里的 type 声明区分，各卡各用、不能混用。
 */
@Component
public class JwtUtil {

    public static final String TYPE_ACCESS = "access";
    public static final String TYPE_REFRESH = "refresh";

    @Value("${nanpo.jwt.secret}")
    private String secret;

    @Value("${nanpo.jwt.access-ttl-minutes:15}")
    private long accessTtlMinutes;

    @Value("${nanpo.jwt.refresh-ttl-days:7}")
    private long refreshTtlDays;

    private SecretKey key() {
        // HS256 要求密钥 ≥ 32 字节
        return Keys.hmacShaKeyFor(secret.getBytes(StandardCharsets.UTF_8));
    }

    public String generateAccessToken(Long userId, String username) {
        return generate(userId, username, Duration.ofMinutes(accessTtlMinutes), TYPE_ACCESS);
    }

    public String generateRefreshToken(Long userId, String username) {
        return generate(userId, username, Duration.ofDays(refreshTtlDays), TYPE_REFRESH);
    }

    private String generate(Long userId, String username, Duration ttl, String type) {
        return Jwts.builder()
                .subject(String.valueOf(userId))
                .claim("username", username)
                .claim("type", type)                              // access / refresh
                .issuedAt(new Date())
                .expiration(Date.from(Instant.now().plus(ttl)))
                .signWith(key())
                .compact();
    }

    /** 解析并校验：签名不对/过期/格式坏抛 JwtException 子类，通过则返回 Payload */
    public Claims parseClaims(String token) {
        return Jwts.parser()
                .verifyWith(key())
                .build()
                .parseSignedClaims(token)
                .getPayload();
    }

    public long getAccessTtlMinutes() {
        return accessTtlMinutes;
    }
}
```

变化点：两套有效期配置、两个公开签发方法、私有的 `generate` 里多了 `claim("type", type)`——**卡的身份证**写在 Payload 里，查票和续卡时靠它分辨。

## Step 3：UserContext——当前会员的储物柜（10 分钟）

新建 `common/UserContext.java`：

```java
package com.cdutetc.nanpo.common;

/**
 * 当前登录人上下文（第16课）。
 * 拦截器查完票把"当前会员"放进 ThreadLocal——
 * 同一个请求线程里，后续任何 Service 都能直接取，不用层层传参。
 *
 * 不清理会串号：Tomcat 线程池复用线程，上一个请求的登录人
 * 可能残留给下一个请求——所以拦截器 afterCompletion 必须 clear()。
 */
public class UserContext {

    /** 第10课预告过的 record：一行定义不可变数据类 */
    public record CurrentUser(Long userId, String username) {
    }

    private static final ThreadLocal<CurrentUser> HOLDER = new ThreadLocal<>();

    public static void set(CurrentUser user) {
        HOLDER.set(user);
    }

    public static CurrentUser get() {
        return HOLDER.get();
    }

    /** 需要登录人的地方用它取——没登录直接抛业务异常 */
    public static CurrentUser require() {
        CurrentUser user = HOLDER.get();
        if (user == null) {
            throw new BusinessException(ErrorCodeEnum.TOKEN_MISSING);
        }
        return user;
    }

    public static void clear() {
        HOLDER.remove();
    }
}
```

两个看点：内部类用了 **record**（第 10 课预告的"一行定义不可变数据类"，先睹为快——userId/username 字段 + 构造 + 访问器全在这一行里）；`require()` 是"取并断言"——没登录就抛 40401 系的 TOKEN_MISSING，业务层只管要人，不管票从哪来。

## Step 4：查票员 JwtInterceptor（20 分钟）

新建 `common/JwtInterceptor.java`：

```java
package com.cdutetc.nanpo.common;

import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;
import org.springframework.web.servlet.HandlerInterceptor;

import io.jsonwebtoken.Claims;
import io.jsonwebtoken.JwtException;
import jakarta.servlet.http.HttpServletRequest;
import jakarta.servlet.http.HttpServletResponse;

/**
 * 查票员（第16课）：统一的令牌校验拦截器。
 * 请求头格式：Authorization: Bearer <accessToken>
 * 校验通过 → 当前用户放进 UserContext，放行；
 * 任何问题 → 抛业务异常（第6课的处理台会转成规范 JSON）。
 */
@Component
public class JwtInterceptor implements HandlerInterceptor {

    @Autowired
    private JwtUtil jwtUtil;

    @Override
    public boolean preHandle(HttpServletRequest request, HttpServletResponse response, Object handler) {
        String auth = request.getHeader("Authorization");
        if (auth == null || !auth.startsWith("Bearer ")) {
            throw new BusinessException(ErrorCodeEnum.TOKEN_MISSING);
        }
        String token = auth.substring(7);   // 去掉 "Bearer " 前缀
        try {
            Claims claims = jwtUtil.parseClaims(token);
            // 长短卡规矩：refreshToken 不能当 accessToken 用（续卡专用，见 /refresh）
            if (!JwtUtil.TYPE_ACCESS.equals(claims.get("type", String.class))) {
                throw new BusinessException(ErrorCodeEnum.TOKEN_INVALID);
            }
            UserContext.set(new UserContext.CurrentUser(
                    Long.valueOf(claims.getSubject()),
                    claims.get("username", String.class)));
            return true;
        } catch (JwtException e) {
            // 过期(ExpiredJwtException)/签名不对/格式坏，都归为"令牌无效"
            throw new BusinessException(ErrorCodeEnum.TOKEN_INVALID);
        }
    }

    @Override
    public void afterCompletion(HttpServletRequest request, HttpServletResponse response,
                                Object handler, Exception ex) {
        // 线程池复用线程，必须清理——否则下一个请求可能"冒充"上一个登录人
        UserContext.clear();
    }
}
```

逐层读懂 `preHandle`：

1. **取头**：`Authorization: Bearer xxx` 是 HTTP 认证的标准头格式（Bearer = "持有者"）。没有头或格式不对 → 40101 请先登录。
2. **验票**：`parseClaims` 一站式校验签名+有效期，坏票抛 `JwtException` → 统一转 40102。
3. **验卡种**：即使长卡是真票（签名有效期都对），`type` 不是 access 也拒——40102。
4. **放行并登记**：`UserContext.set(...)` 把会员放进储物柜，`return true` 放行进 Controller。

而 `afterCompletion`（请求完全结束后回调）里的 `clear()`——**本课最重要的一行**。Tomcat 用线程池处理请求，线程是复用的：不清理，下一个复用此线程的请求可能捡到上一个请求的登录人，拿着别人的身份下单。

> 小知识：拦截器抛出的 BusinessException 照样会被第 6 课的 `@RestControllerAdvice` 接住——查票失败也回规范信封，全店口径一致。

## Step 7：续卡窗口 /refresh（15 分钟）

**① `vo/LoginVO.java` 升级为双卡**（整个换掉）：

package com.cdutetc.nanpo.vo;

import lombok.Data;

/**
 * 登录成功小票（第16课升级：长短两张卡）。

**③ `UserService` 升级**：登录改为发双卡（把原 login 里 set token 的三行换成调 buildLoginVO），并新增 refresh 方法（import 补 `Claims/JwtException/RefreshRequest`）：

```java
    /** 登录：验证通过发长短两张卡 */
    public LoginVO login(LoginRequest req) {
        User user = userRepository.findByUsername(req.getUsername())
                .orElseThrow(() -> new BusinessException(ErrorCodeEnum.LOGIN_FAILED));
        // 用户不存在和密码错误统一报错——不帮攻击者缩小爆破范围
        if (!passwordEncoder.matches(req.getPassword(), user.getPassword())) {
            throw new BusinessException(ErrorCodeEnum.LOGIN_FAILED);
        }
        return buildLoginVO(user);
    }

    /** 续卡：长卡换新短卡（长卡本身沿用；生产建议每次轮换 refreshToken） */
    public LoginVO refresh(RefreshRequest req) {
        Claims claims;
        try {
            claims = jwtUtil.parseClaims(req.getRefreshToken());
        } catch (JwtException e) {
            throw new BusinessException(ErrorCodeEnum.TOKEN_INVALID);
        }
        // 短卡不能来续卡——各卡各用（用 accessToken 调这里会被拒）
        if (!JwtUtil.TYPE_REFRESH.equals(claims.get("type", String.class))) {
            throw new BusinessException(ErrorCodeEnum.TOKEN_INVALID);
        }
        User user = userRepository.findById(Long.valueOf(claims.getSubject()))
                .orElseThrow(() -> new BusinessException(ErrorCodeEnum.TOKEN_INVALID));
        return buildLoginVO(user);
    }

    private LoginVO buildLoginVO(User user) {
        LoginVO vo = new LoginVO();
        vo.setAccessToken(jwtUtil.generateAccessToken(user.getId(), user.getUsername()));
        vo.setRefreshToken(jwtUtil.generateRefreshToken(user.getId(), user.getUsername()));
        vo.setAccessExpiresIn(jwtUtil.getAccessTtlMinutes());
        vo.setNickname(user.getNickname());
        return vo;
    }
```

**④ `UserController` 加续卡接口**：

```java
    // 续卡：refreshToken 换新的 accessToken（短卡过期了不用重新输密码）
    @PostMapping("/refresh")
    public Result<LoginVO> refresh(@RequestBody RefreshRequest req) {
        return Result.success(userService.refresh(req));
    }
```

（import 补 `RefreshRequest`。）`refresh` 的逻辑链：验长卡签名 → 确认卡种是 refresh（短卡来续？拒）→ 按卡里的 userId 找回用户 → 重新发一对卡。

**③ script 开头加会员管理，并给两处 fetch 换带卡的头**：

```js
    // ===== 会员（第16课）：令牌管理与登录 =====
    // 所有需要亮卡的请求都带上 Authorization: Bearer <accessToken>
    function authHeaders() {
        const headers = { 'Content-Type': 'application/json' };
        const token = localStorage.getItem('accessToken');
        if (token) headers['Authorization'] = 'Bearer ' + token;
        return headers;
    }

    function register() {
        fetch('/register', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ username: username.value, password: password.value })
        })
        .then(r => r.json())
        .then(result => alert(result.code === 200 ? '办卡成功，请登录' : result.msg));
    }

    function login() {
        fetch('/login', {
            method: 'POST',
            headers: { 'Content-Type': 'application/json' },
            body: JSON.stringify({ username: username.value, password: password.value })
        })
        .then(r => r.json())
        .then(result => {
            if (result.code === 200) {
                // 两张卡分开收好：短卡随请求带，长卡只在续卡时用
                localStorage.setItem('accessToken', result.data.accessToken);
                localStorage.setItem('refreshToken', result.data.refreshToken);
                who.textContent = '会员：' + result.data.nickname;
            } else {
                alert(result.msg);
            }
        });
    }
```
