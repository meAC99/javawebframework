# 第7课 · 验证、提交与练习

## 一、requests.http 追加

```
### 7.1 H2 控制台入口（预期 302 跳转；登录在浏览器完成）
GET http://localhost:8080/h2-console
```

发送后预期：状态码 `302 Found`（跳转到 `/h2-console/` 登录页）——控制台登录这种"给人看的页面"还是浏览器方便，REST Client 负责确认它"活着"。

## 二、验证清单（全过才算下课）

**1. 启动日志两条证据**

- `H2 console available at '/h2-console'. Database available at 'jdbc:h2:mem:nanpo'`
- `HikariPool-1 - Starting...`（连接池就位）

**2. 发送 7.1**：预期 302。

**3. 浏览器登录 h2-console**

`http://localhost:8080/h2-console` → JDBC URL 填 `jdbc:h2:mem:nanpo`、用户名 `sa`、密码空 → 成功进入。

**4. 在控制台执行**

```sql
SELECT 1+1;
```

预期返回 `2`；左侧对象树里 `PUBLIC` 下**没有任何表**（正常——还没有实体）。

**5. 回归：加数据库不动业务**

- 重发 **2.1 查菜单** / **2.2 正常点单** → 和第 6 课一致（此刻业务代码还没用上数据库，菜单还是 static Map——下一课才搬家）
- 重发 **6.1 佛跳墙** → 仍是 `{code:40401}`

## 四、课后练习

1. **换个库名**：把 yml 里的 URL 改成 `jdbc:h2:mem:nanpo2`，重启，用新 URL 登录控制台成功；再用旧 URL `jdbc:h2:mem:nanpo` 登录——报什么错？（体会：mem 后面的串就是"库名"，两个名字是两个独立的库。做完改回 `nanpo`。）
2. **日志侦探**：把 `show-sql` 临时改成 `false`，重启，对比启动日志有什么变化；再改回 `true`（第 8 课开始它就是你的"眼睛"）。
3. **思考题**：课程用 H2 内存库是为了教学方便。真实项目几乎都用 MySQL/PostgreSQL 这类独立数据库，理由你能列出几条？（提示：持久化、并发容量、多应用共享、权限管理——第 19 课你会亲手把 H2 换成 MySQL 容器，改动量小到你会回来感谢这节课的分层。）

## 五、下一课预告

账本建好了，翻开来却是空的——因为 `ddl-auto` 只按**实体**建表，而你还没有一个实体。

下一课，你将写下第一个 JPA 实体 `Menu`：一个类、几个注解，启动的瞬间 `t_menu` 表就会自动出现在控制台左侧；6 道菜会由一个"开市准备"组件自动装进库里；然后你删掉 `WaiterController` 里那个从第 2 课活到现在的 static 菜谱——**改价终于不用改代码了**。从那节课起，`show-sql` 打开的 SQL 日志将成为你的"透视眼"。
