# 第7课 · 动手做：账本三件套 + 一个著名坑位

共 5 步。**Step 3 的坑是本课灵魂，千万别跳过**——按顺序做，先踩坑再填坑。

## Step 1：pom 加两件套（先不加第三件）（10 分钟）

在 `pom.xml` 的 `<dependencies>` 里追加：

```xml
<!-- 第7课：账本三件套之 H2 内存数据库 + JPA -->
<dependency>
    <groupId>com.h2database</groupId>
    <artifactId>h2</artifactId>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>
```

看懂这两行：

- **h2**：数据库本体。`<scope>runtime</scope>` 表示编译期不用它（你的代码里不会 `import org.h2...`）、只在运行时需要——比默认的 compile 更精准。
- **starter-data-jpa**：JPA 全家桶——Hibernate（ORM 实现）、JPA 接口、事务管理器，还会顺带装配**连接池**（HikariCP）。

> 注意：第三件套（spring-boot-h2console）**故意先不加**——Step 3 的坑实验需要它缺席。

## Step 2：application.yml 加三段配置（15 分钟）

改成下面这样（新增 `datasource`、`h2.console`、`jpa` 三段，都在 `spring:` 底下，注意缩进）：

```yaml
spring:
  application:
    name: nanpo-xiaochao

  # 第7课：账本（数据源）四要素
  datasource:
    driver-class-name: org.h2.Driver
    url: jdbc:h2:mem:nanpo    # 内存库：应用一停数据就清零（第19课换 MySQL 容器持久化）
    username: sa
    password:

  # 第7课：H2 网页控制台——注意还需要 pom 里引入 spring-boot-h2console 模块（Boot 4 拆分）
  h2:
    console:
      enabled: true
      path: /h2-console

  # 第7课：JPA——实体怎么变成表
  jpa:
    hibernate:
      ddl-auto: update        # create/create-drop/update/none 四个取值课堂对比
    show-sql: true            # 控制台打印 SQL，第8课起"眼见为实"看 JPA 生成的语句

server:
  port: 8080
```

逐段拆解：

**数据源四要素**（连数据库的"地址+门牌+钥匙"）：

| 要素 | 值 | 含义 |
|---|---|---|
| driver-class-name | `org.h2.Driver` | 用哪个驱动程序连库 |
| url | `jdbc:h2:mem:nanpo` | 连哪种库、连到哪：`jdbc` 协议 → `h2` 数据库类型 → `mem` **内存模式** → `nanpo` 库名 |
| username | `sa` | H2 默认管理员 |
| password | （空） | 教学库不设密码 |

**ddl-auto 四个取值**（决定 Hibernate 启动时对表结构做什么——本课还没有表，先背口诀，第 8 课见效）：

| 取值 | 行为 | 场景 |
|---|---|---|
| `create` | 每次启动**删了重建**所有表 | 一直空表起步，数据必丢 |
| `create-drop` | 启动建表、**关闭删表** | 单元测试 |
| `update` | 对比实体，**只加不改**（缺表建表、缺列加列） | 开发期常用（本课程用它） |
| `none` | 什么都不做 | 生产环境（表结构由 SQL 脚本/DBA 管理） |

**show-sql: true**：把 Hibernate 生成的 SQL 打印到控制台——第 8 课起，你写的每个数据库操作都能"眼见为实"。

## Step 3：重启，访问 /h2-console——坑来了（15 分钟）

```bash
./mvnw spring-boot:run
```

先观察两个细节（对比第 6 课的启动日志）：

1. 多了一行 `HikariPool-1 - Starting...`——连接池已悄悄就位（自动配置的又一例证：你只配了 URL，池子是它送的）
2. 没有 H2 控制台的任何字样

现在浏览器打开 `http://localhost:8080/h2-console`——**你看到的是**：

```json
{"code":40404,"data":null,"msg":"访问路径不存在"}
```

配置明明写了 `enabled: true`，为什么不生效？！先欣赏一件事：这个 404 被第 6 课的客诉处理台接成了规范信封——要是没有它，你会看到更懵的 Whitelabel 页。

**坑的机理**：Spring Boot 4 做了一次"模块化拆分"——原来住在 `spring-boot-autoconfigure` 大 jar 里的几十种自动配置，被拆成了一堆独立小模块。**H2 控制台的自动配置，被拆进了 `spring-boot-h2console` 模块**。你没引它，`spring.h2.console.*` 这段配置就没人读、没人实现。

一句话总结（值得抄进笔记）：**配置是"愿望"，自动配置模块是"实现愿望的人"——人不在场，愿望就是空话。** 这也解释了第 1 课的伏笔：为什么引了 starter-webmvc 就有 Tomcat——因为那个 starter 把对应自动配置模块拉进了类路径。

## Step 4：填坑——补上第三件套（10 分钟）

`pom.xml` 再追加：

```xml
<!-- Boot 4 坑位：H2 控制台的自动配置被拆成独立模块，不引入则 /h2-console 永远 404 -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-h2console</artifactId>
</dependency>
```

重启。这次启动日志里多了一行**关键证据**：

```
H2ConsoleAutoConfiguration : H2 console available at '/h2-console'. Database available at 'jdbc:h2:mem:nanpo'
```

这行日志就是"实现愿望的人"上岗的宣言——`H2ConsoleAutoConfiguration` 这个类的名字直接告诉你：自动配置，开工了。

## Step 5：登录控制台，看一眼空账本（10 分钟）

浏览器打开 `http://localhost:8080/h2-console`，登录框按下面填：

| 字段 | 填什么 |
|---|---|
| JDBC URL | `jdbc:h2:mem:nanpo`（**必须和 yml 里完全一致**，默认值是 `jdbc:h2:mem:testdb`，不改必错） |
| User Name | `sa` |
| Password | 留空 |

点 Connect 进入控制台。你会看到：上方一个 SQL 输入框，左侧一棵数据库对象树——展开 `PUBLIC`……**什么表都没有**。

这是对的！本课只建了"账本"（数据库）本身，还没有任何"账页"（表）。表从哪来？`ddl-auto` 只会按**实体**建表——而你的第一个实体 `Menu`，就是下一课的主角。

在 SQL 框里输入一句验证连通性，点 Run：

```sql
SELECT 1+1;
```

返回 `2`——你已经在直接对数据库说话了。

> **常见报错速查**
>
> | 现象 | 原因 | 解法 |
> |---|---|---|
> | 登录报 `Database "..." not found` | JDBC URL 和 yml 里的不一致（最常见是没改默认的 testdb） | 两边统一成 `jdbc:h2:mem:nanpo` |
> | `/h2-console` 返回 40404 信封 | 没引 `spring-boot-h2console` 模块（本课的坑） | pom 补依赖重启 |
> | 启动报 yml 解析错误 | 缩进用了 Tab / 层级没对齐 | 全用空格，对照 Step 2 |
> | `Wrong user name or password` | 用户名没填 sa / 密码填了东西 | sa + 空密码 |
