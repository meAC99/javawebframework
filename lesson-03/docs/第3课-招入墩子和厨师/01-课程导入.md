# 第3课 · 课程导入：招入墩子和厨师

## 上一课发生了什么

店能点菜了，但你的 `WaiterController` 是个 78 行的"全能服务员"：背菜谱、接单、验菜、算价，循环里还亲自炒菜（`[服务员] 炒好了...`）。南坡饭点一来，这位员工必倒无疑。

今天你招两个人：**墩子**（SideDishService，配菜）和**厨师**（CookService，炒菜）。服务员只干前厅的事：接单、验菜、算账。这就是**分层**——一个类只负责一类事（单一职责），出问题去哪找、新功能往哪加，一目了然。

```
改造前：服务员（什么都干）
改造后：服务员 → 墩子（配菜） → 厨师（炒菜）
```

这节课你还会第一次**动手删别人的代码**：第 2 课里"服务员炒菜"那两行打印将被删除——活交给新员工，旧代码就该走。真实工作里，"删代码"往往比"加代码"更需要判断力。

## 本课你将学会

1. 为什么要分层：Controller 和 Service 各自的职责边界
2. 建一个 service 包，写出只干一件事的类（单一职责原则）
3. 在一个类里调用另一个类的方法，形成调用链
4. 通过控制台日志观察一次请求的完整流转

## 一个先想清楚的问题：调用链上的"人"怎么来？

服务员要用墩子和厨师，就得先"有"他们的对象。Java 里获得对象最直觉的办法是 `new`：

```java
private final SideDishService sideDishService = new SideDishService();
```

这节课我们就先这么写——它能跑。但它埋着一个大问题：**员工由服务员自己招**，谁都能 new、各new各的、没法统一管理。这个问题这节课先不解决（你甚至可以故意感受一下它的别扭），下一课的主角就是它。
