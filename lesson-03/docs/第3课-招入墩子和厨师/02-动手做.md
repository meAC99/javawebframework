# 第3课 · 动手做：拆出厨房，形成调用链

共 3 步：建两个类 → 改服务员 → 重启验证。注意本课**有删有改**，不是纯新增。

## Step 1：建 service 包，墩子和厨师上岗（15 分钟）

创建包 `com.cdutetc.nanpo.service`，写两个类。

`service/SideDishService.java`——墩子：

```java
package com.cdutetc.nanpo.service;

/**
 * 墩子（配菜员）：只负责配菜这一件事——单一职责。
 * 第3课：暂时还是普通 Java 类，由服务员自己 new 出来（第4课交给容器管理）。
 */
public class SideDishService {

    public void prepareSideMaterial(String dishName, int count) {
        System.out.printf("[墩子] %s x %d 配菜完成%n", dishName, count);
    }
}
```

`service/CookService.java`——厨师：

```java
package com.cdutetc.nanpo.service;

/**
 * 厨师：只负责炒菜这一件事——单一职责。
 * 第3课：暂时还是普通 Java 类，由服务员自己 new 出来（第4课交给容器管理）。
 */
public class CookService {

    public void cookDish(String dishName, int count) {
        System.out.printf("[厨师] %s x %d 炒菜完成%n", dishName, count);
    }
}
```

注意两件事：

- 这两个类**头上一根注解都没有**，就是个普通 Java 类——这是故意的，下一课的悬念就藏在这里。
- 每个类只有一个业务方法。判断拆分是否合理的小技巧：能不能用一句话说清这个类干什么？说不清，就该再拆。

## Step 2：改造服务员——删代码 + 加调用（20 分钟）

修改 `WaiterController.java`，改三处：

**① 类注释追加一行演进记录**（这个类的注释从这节课起就是一部"店史"，每课更新）：

```java
/**
 * 服务员。
 * 第2课：一个人包揽所有活——背菜谱、验菜算账、还要顺手"炒菜"。
 * 第3课：店里招人了——配菜交给墩子(SideDishService)、炒菜交给厨师(CookService)，
 *        服务员只负责接单、验菜、算账，形成调用链：服务员 → 墩子 → 厨师。
 */
```

**② 类里声明两个员工（手动 new，先能跑）**——加在 `MENU` 定义之后：

```java
    // 第3课：服务员自己"招人"——手动 new。
    // 想想有什么问题：谁都能 new 一份、无法统一管理、多个服务员无法共享同一批员工……
    // 这些问题正是第4课 IoC 容器要解决的
    private final SideDishService sideDishService = new SideDishService();
    private final CookService cookService = new CookService();
```

**③ 循环里"炒菜"换人**——删掉这两行：

```java
            // 删除：服务员不再亲自炒菜
            System.out.printf("[服务员] 炒好了 %s x %d%n", dishName, count);
```

换成（位置就在算价代码之后、`OrderItem` 组装之前）：

```java
            // 第3课：厨房分工——墩子先配菜，厨师再炒菜。
            // （第2课的"[服务员] 炒好了"打印已删除：炒菜不再是服务员的活）
            sideDishService.prepareSideMaterial(dishName, count);
            cookService.cookDish(dishName, count);
```

别忘了在文件顶部补 import：

```java
import com.cdutetc.nanpo.service.CookService;
import com.cdutetc.nanpo.service.SideDishService;
```

**先删后加的顺序值得体会**：分工的本质是"把活从一个人身上拿走，交给更合适的人"。只加人不删活，那不叫分工，叫堆人。

## Step 3：重启，观察调用链

```bash
./mvnw spring-boot:run
```

启动后别急着看网页——先想清楚：这次改动之后，`/menu` 的返回会变吗？点单的 JSON 会变吗？

**答案：都不会变。** 我们只改了"厨房内部谁干活"，没动对外的接口——这正是分层的第一笔红利：**内部怎么重构，对外承诺不变**。下一文件用日志和请求验证这一点。

> **坑**：如果启动报 `找不到符号 SideDishService`，检查类是不是建在了 `service` 包、import 是否拼对；如果日志里既有 `[服务员] 炒好了` 又有 `[墩子]`，说明你没删旧打印——回去补删。
